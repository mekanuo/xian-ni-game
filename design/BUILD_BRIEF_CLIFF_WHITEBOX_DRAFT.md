2026-09-11。**仅供 0.7 发布后决定是否启动白盒。当前 0.7 尚未部署，本稿不是生产批准，也没有开始构建。** 本轮只读冻结的运行规则与设计资料，仅新增本文；以下坐标、周期、投影及路线都是待测候选，不代表模型或浏览器已通过。

- 最大风险只有一项：**在手机普通近景中，玩家能否从第一段“选穿越时机”转为第二段“选实际挡石的凹位”，并以零灵力亲自往返。**
- 继承 [风险评审](CLIFF_NEXT_RISK_REVIEW.md)、[首版玩家承诺](GAME_DESIGN.md)、[内容路线图](CONTENT_ROADMAP.md) 和 [已认可角色扮演方向](../docs/ROLEPLAY_DIRECTION.md)。原 B 原样生产仍被否决。

## 1. 先把现有镜头与 HUD 算清楚

依据本轮只读的 [显示比例](../src/game/display.ts)、[镜头](../src/game/scene.ts) 与 [界面样式](../src/style.css)。这里是源码推算，不是新浏览器测量；实际 DOM 边界仍须在白盒实测。

当前非石驿地图的 CSS 世界缩放取以下三者最大值：基础世界比例、视口宽／地图宽、视口高／地图高。基础比例在较短屏边小于 600 时为 0.85，否则为 1。高 DPR 提高画布分辨率，不把 DOM 按钮缩小，也不增加世界视野。镜头边界就是整张地图；普通回身镜头向人物上方领先 55 世界单位，跟随有缓动。

**0.7 已暴露的限制不能重演。** 390×844 下，小集 1400×1000 的缩放为 0.85，世界可视高约 992.94，纵向平移余量仅约 7.06。处于顶边的世界点 y=220 即使拖到边界，其 CSS y 仍约为 181–187；这正可能落在观察条／暂停条所在区域。目标真实存在、世界坐标合法、DPR 达标，均不能让它变成可点击地面。

手机当前竖屏样式具有这些实际约束：

| 区域 | 390×844、模拟安全边距为 0 时的源码边界 | 本候选如何避开 |
|---|---|---|
| 身份及目标 | 上边 10；身份栏宽 150，目标从 x=172 起；目标文字高度随换行变化 | 不把源头放在顶端；目标保持一句，不按固定字数推断它只占一行 |
| 顶栏按钮 | 新竖屏覆盖规则把顶边改为 108；按钮最小高度 44 | y≤152 不安排必须点中的脚点 |
| 观察条／暂停条 | 顶边 164，控件最小高度 44；观察展开后更高 | 关键源头、地面和退身区规划在 y≥230；展开面板只在安全处主动阅读 |
| 底部术法栏 | 底边 10，普通术法高 61，加上下内边距和边框，常态顶边约 759 | 不用底边空隙作为操作路线 |
| 回身、附近互动、帮助 | 底边约 101–103，加至少 44 高；常态大致从 y=697 附近开始 | 必须点击的落脚处规划在 y≤610 |
| 即时提示 | 底边 161，即底缘 y=683；提示高度由实际内容决定；举术／牵物可把它继续上移 | 第一轮危险带不用频繁长通知遮地；警告主要在实际源头和线路。正文换行、放大文字与术法展开仍须逐态查实际矩形 |

**候选保守决策窗为 CSS x=20–370、y=230–610。** 它是布局目标，不是声称这块区域永远没有 DOM；实际脚点和人物身体仍要逐点核对可见、无遮挡。正常运行中的来石预告必须在窗内可辨，不能只在手动暂停时成立。

## 2. 地图外壳与局部坐标候选

地图候选尺寸 **1900×2200 世界单位**。外壳留白用于避开镜头边界，不意味着把所有面积铺成可探索内容。只有下述窄侧道与安全台可行走，外围是明确不可通行的崖体；不添加沿地图大边框绕开整段的隐形捷径。

| 代表视口 | 候选 CSS 缩放 | 世界可视宽×高 | 推算结论 |
|---|---:|---:|---|
| 390×844 DPR3 | 0.85 | 458.82×992.94 | 两段都可以在地图内部居中，不再几乎等高铺满整图 |
| 1280×500 DPR1 | 0.85 | 1505.88×588.24 | 不能误套“宽≤1000 且高≤500”的横屏 HUD 样式；这一视口仍须按真实桌面 HUD 查可见性 |
| 1440×900 DPR2 | 1 | 1440×900 | DPR 受现行像素预算约束，密度约 1.964；CSS 世界缩放仍为 1 |

两段及远端的关键站位 x 在 800–1050、y 在 850–1640。按照回身后的稳定镜头，三个视口都不应触及地图边界。例如手机站在 (890,1640)，镜头中心约为 (890,1585)，可视底边约 2081.47，小于 2200；短窗口在 x=800 的可视左缘约 47.06，大于 0。**这些算术只排除静态边界夹死，不证明缓动途中、实体遮挡或触摸输入已成立。**

### 拓扑先于装饰

入口台 → 第一段西台 → 横过落石带 → 第一段东台 → 安全连接小径 → 第二段起步湾 → 外槽或内凹路线 → 远端认路台 → 按实际来路返回 → 入口近身报告。

入口和安全连接段不再设置危险。连接段只把第一段东台接到第二段起步湾，不能提前接到内凹或远端；它绕开两条落石线路，不让玩家在尚未看到第二段时受击。地形外围与连接弯角的完整碰撞多边形留待白盒落实；若实际导航存在绕过第一段、从连接段直达远端或跨崖抄近路，当前候选失败，不能以路线脚本约定“不要那样走”掩盖。

### 第一段：短横穿

| 项目 | 待测世界坐标／范围 | 必须成立的事实 |
|---|---|---|
| 入口台、岑叔 | 入口脚点 (800,1040)，人物候点 (755,1040) | 不在落石线路；拒绝试走可以在原口结束 |
| 西台 A、东台 B | A=(800,850)，B=(980,850) | 两处都有至少约 52×52 的可安全选脚点区域；这是可站脚中心区域，不是把身体包络省掉后的原始地面宽度 |
| 短横穿中心线 | A→B，y=850，原始通路厚度候选 80 | 无别的水平绕路。身体完整越过落石线后才算这一段通过 |
| 松石源 S1 | 可见出石口 (890,700)，裂口表现向上不超过约 20 | 固定向下落，绝不追踪人物；源头不能出生在会立即吞掉石头的实体墙内 |
| 危险线路 | x=890，由出石口向下经过横穿处 | 来源、在途石头与横穿的交点连续可见；边沿不可从源头背后绕掉整段 |

危险狭槽与外围崖体的交接必须让射弹确实离开出石口、通过步行带，同时让人物不能绕到源头背后跳过危险。这里尚未提交完整墙体矩形清单，不能仅凭中心线宣布合法。白盒先检查首个碰撞对象，防止石头刚发出就被背景崖体吃掉而得到假的无伤路线。

### 第二段：外槽与真实内凹

| 项目 | 待测世界坐标／范围 | 作用 |
|---|---|---|
| 起步湾 L | (890,1640) | 两轮落石都可站稳察看；来石不会追到这里 |
| 同一松石源 S2 | (930,1380)，裂口表现向上约 20 | 这一局部只有一个源头；发出固定、可见的同轮碎石来向 |
| 外槽路线 | L→O=(800,1620)→T=(920,1398)→E=(840,1400) | O→T 沿主石来向逆向走，原始路宽候选 70，身体可用余量明显小于内侧。玩家不能只把整段当作一次横穿 |
| 假凹位 D | (860,1510)，属于外槽本身 | 看似退开，但仍在 S2→O 的实际来向上；不得画成有岩壁保护的可靠洞穴，再用伤害打脸 |
| 岩鼻 R | 左上 (900,1470)，宽 100，高 75 | 身体与来石都撞实际边界；画出的护壁就是碰撞面 |
| 内凹 H | (1050,1555) | 源头朝这里来的碎石先撞岩鼻。候选可站脚区域约 56×56，不能用一个点代表整处安全 |
| 内侧上口 U | (1010,1420) | 从 H 沿岩鼻右侧上行抵达，站在两条来向之外；随后短横过上方开口到 E |
| 内侧路线与远端 E | L→H→U→E；E=(840,1400) | 内侧原始通路宽约 106；需要实际绕过岩鼻。E 本身须有稳定立足区，可认出下方已经走过的旧路转折，不增远端恢复点 |

**此候选比上一稿多明确一项最小环境假设：S2 每轮是一颗主石沿外槽、另一片碎石朝内凹方向，被 R 实际截住。** 两条都是确定的直线，来自同一可见松动，不做反弹、分裂追踪或滑坡模拟。它用于使“岩鼻保护”具有真实首撞证据：如果石头本来就永远不朝凹位来，不能把站在线外包装成遮挡玩法。

这是待否决的增量，不是已批准新机制。若必须增加更多源头、随机散射或更密集的弹幕才能体现掩蔽，应停止这个候选。若单一来石线路已经能证明等价的实际遮挡关系，可以删去第二片碎石，但要重新证明它仍区别于两次等空档。

完整可行走面只连接列出的两条路线；不存在横穿岩鼻或从外槽外侧走一条更宽无风险平行线。尤其不能把最短寻路自动导向内凹后，再声称玩家作出了掩蔽选择。应记录直接点远端实际选择的路径；若它无视第二段的来向仍稳定得到同样结果，候选的最大风险没有通过。

S2 的可见裂口上缘在 L 处约为 y=230.75，刚进入保守窗，因此这是本布局最敏感的静态假设。**若真实源头表现需要高于出石口 20 单位，或目标文字／观察条侵入 y=230，本组纵向距离必须缩短或局部位置重排；不能假称“DPR3 就能看见”。** A、B 远侧的 52×52 选脚区映射为约 44.2 像素，其边缘也接近保守水平界限，应检查完整区域而非只验中心。

上述投影还没有覆盖从 H 上行的镜头缓动、点击走到边沿后的构图，以及通知和举术新增按钮。白盒必须在这些实际状态再次取证。允许人在安全台用真实单指看路，不能在伤害窗口里强迫拖图再急忙点脚点；至少一趟正常速度零灵力往返无需手动暂停或缩成全图。坐标算得进屏而身体被 HUD 截掉，仍判失败。

## 4. 待测节拍，不靠第二段加速区分

第一轮候选 **两段都采用 2.6 秒一轮、出石前 1.0 秒可见松动，落石沿现有约 220 世界单位／秒的速度前行**。这是白盒起点假设，不是推荐的最终难度，更不是已通过数值。源头在安全观察期间也正常经历节拍；不同到达相位会见到不同阶段。两处相位可错开，但不得把“恰好同时错开”作为唯一可行条件。

第一段横穿中心线长 180，按既有步速 160 粗算约 1.125 秒；等待当前石头确实离开步行带，再横过应有可测余量。第二段 O→T 逆着来向走约 252 世界单位；忽略身体半径的理想化估算中，同向两颗石头之间供人逆行通过的条件约为 `距离÷160 + 距离÷220`，约 2.72 秒，已经长于候选间隔 2.6 秒。身体尺寸、真正路径、出石偏移与动作延迟只会要求进一步检查，不能把这行算术当成“外槽必定中石”的证明。

这份差异来自横穿与沿槽逆行的几何关系、以及实际岩鼻提供的另一条路径；没有把第二段单独加速。但它仍可能只形成“绕一条明显长路”的浅选择：若正式模型证明等一个相位就可两段直走、外槽边缘能无风险平移过去、或内侧路径成为全自动默认，本候选按上一份评审否决，不能把周期再减小来保住结论。

H 与 U 应允许停过两轮，无需追下一拍。H→U 的安全来自实际遮挡和站在线外；U→E 的最后短横过依然要看清来向。这是用已学会的时机判断收尾，不发明第三种危险。返程反向读同一环境，不重置山体或追加新源头；已掌握路线后变得顺手是合理成长。

## 5. 最小行为、有限报告与重开

只保留实际到过哪处、是否从远端按路走回、已经向入口人物说明的范围，以及当前石头／预告阶段。人物、危险与判断结果均以真实动作成立；没有根据玩家当前坐标自动回填完整旅程的入口。

岑叔留在入口做自己的事，不领路、不替玩家试石；他只能亲见出发与返回，内部经过来自近身报告。半程回来可以说清半程；到达远端之后败退、重试或重开，不等于亲自走回。完成实际往返后一次报告只改变用途说明：步行曾试过，运石车仍不走，自然危险仍在。重复说明不领奖，也不清石头。

白盒默认独行，起点体力 4、灵力 0、伤药 0；另有显式的普通资源预设，用于现有定向护符对照。预设属于公开合成白盒初态，不能冒充真实旧档。不给当前生产存档写入新内容，不设置远端休息或中途回血。

暂停、对白和失焦都冻结人物、预告、在途石头及待办。恢复从实际阶段继续，不重置为满额空档；若本轮没有独立快照导入功能，就只声明已验证暂停，正式续存仍未验证。重开回到所选完整初态，包括阶段、人物、用途牌和资源；它不是回入口并偷偷保留完成史。

## 6. 决定是否继续的最窄验证

| 路径 | 必须得到的实际证据 | 否决信号 |
|---|---|---|
| 零灵力完整往返 | 独行 4 体力／0 灵力／0 药，正常速度、无暂停、无补给、无重试走到 E 并回入口；代表正确路线仍为 4 体力，真实近身报告和重开成立 | 靠一格体力、受击无敌或脚本逐帧抢窗挤过去 |
| 判断对照 | 第一段看清空档横穿；第二段直接点远端的实际路径与选 H 的路径对照，记录可见来石、首撞岩鼻、身体路径和伤害差异 | 两段只差等更久，或内凹保护只是无伤标签，没有实际挡石 |
| 到达相位 | 从同一初态正常等待到预告前、预告中、刚出石后再出发；去回均能在实际安全处重新等待和选择 | 仅固定录像秒点可过；某相位无零资源退路 |
| 稳定立足与失败回头 | A、B、L、H、U、E 各停两轮；第一段带内、第二段外槽故意迟走或回头，受击可解释，恢复控制后能走回已见安全处，再选择继续或退出 | 凹位偶然安全、一次失误连续锁死、靠自动传到正确凹位兜底 |
| 手机画面与输入 | 三视口分别检查正常 HUD、观察条、通知、暂停、举术后的实际矩形；手机真实单指点地／看路，无触点坐标注入；关键身体、源头、退身地面同屏 | 再现 (1220,220) 式边界锁死；只验中心点、只看模型、只在全图或暂停时看得懂 |
| 有资源变式 | 正确与错误来向护符各一次，消耗与阻挡沿现有规则，下一颗仍真实发生；不因施术成功补到达或报告 | 任意朝向全挡、用一次障使整段永久安全 |

### 复用引擎的具体限制（只读核对，未运行）

当前 model.ts 的地形是矩形障碍，身体以17单位向四边扩张；导航先试直线，再使用40单位网格的广度搜索，最后裁短路径，并不是连续多边形导航或A*。因此外槽70宽只剩约36宽的身体中心带，斜放之后可能没有连贯的40单位网格节点。白盒先用现有真实 move 操作逐点检查两路可达与转角，不为新图偷偷缩小身体或修改全游戏导航。前文“A*”泛称应按此实际实现理解。
