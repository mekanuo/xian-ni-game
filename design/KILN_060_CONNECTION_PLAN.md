## 2. 溪道北侧土路

核对来源：`content.ts` 的溪道 ground、obstacles、entities，`life-content.ts`、`journey-content.ts` 的追加实体，`scene.ts` 的 `paintCreek`，以及实际查看的 `creek-ground.png`。

- 路牌和回到点位于北侧土路定义的 (180,270,1310,150) 内，接现有北路。采用西向箭头，不声称新增一条穿过北缘树林的可走岔道。
- 溪水实体区为 (640,455,150,165)，回到点在其北方，玩家 17 半径也不触水。眺台的西壁从 x=1070 开始，闭合入口在 (1070,235,30,125)；选址不借打开眺台或架起雨棚桥获得通行。
- 最近一组北侧旧互动器物是眺台侧托 (970,290) 和入口木梁 (1080,290)，新牌距侧托约 351，不与其互动范围争抢。小舟、绳扣、器具袋和许照均留在南面原位。
- 北侧附加灌木位于 (450,200)、(850,210)，雨棚图像覆盖约 x=880–1300、y=380–600。路牌、玩家回到点与当前换图逻辑可能放置的同行者 (805,355) 不落入这些建筑图像范围。北路的地板原画已实际看过；尚无新牌合成后的浏览器截图，不能据此宣称所有手机视口均无遮挡。

零资源的现有连路采样：

`(170,760) → (300,740) → (300,340) → (700,315)`，随后可到新回到点 `(760,315) → (1000,390) → (1570,420)`，继续走向旧工棚路牌。新牌整矩形设为实体时，真实寻路在牌南侧经 `(680,400)` 绕到互动位；不会要求穿牌。

这条路不触发取袋、登眺台或雨棚坐垫事件。旧工棚仍须按原条件检查器具袋，石渡仍须按原条件检查试环；新增出口不能替这两个旧出口放宽门槛。

连接下游的采样路明确从取水棚东缘外侧经过，不能用一条从新出口直点旧入口的线来证明画面不穿屋顶：

连接上游可用 `(500,570) → (560,400) → (880,400) → (1150,400)`；最后位置在固定眼西侧，可继续按旧规则走近取回压扣，不需要跨湿渠。其间不点分水板、不以互动当寻路。

## 4. 路牌、换图和事件边界

既有 `wayfinding` 对“旧窑”生成宽 104 的牌面，局部 y=-63…-25，文字中心 (-6,-44)。因此溪道牌面约 x=568–672、y=252–290，字心 (614,271)；旧渠牌面约 x=408–512、y=387–425，字心 (454,406)。必须让文字继续作为路牌容器内的同坐标子物件；出口不参加普通姓名避让，不能再把它改回通用 y+15 标签。

解锁条件在**两张既有地图的新出口**上保持一致：0.5 回程已完成即可，包括独行完成；不要求 `recordedShared` 或许照跟随。新出口出现不代表旧窑已走通。溪道／旧渠进窑只记到访；旧窑穿到另一端并实际换入既有场景，才记录相应通过事实。旧出口和驿前二选一出发仍保留。

旧渠边界必须保留：

- 切出时继续执行原有放下牵物、打断工作、维持截水板／分水板支持以及清理来水过渡。不能把已安装压扣返还背包，不能把固定截水板解除，也不能顺带复水、清框或验水。
- 新落点不在主渠／旁渠连同 17 安全边界内，不制造落地即来水撤离。西岸不进入 x=1300–1530、y=480–900 的山兽弯道。
- 不自动触发 `canal_inspect`、`canal_tub`、邵禾报告或桌案落笔；`method`、共同察看／验水、压扣所在位置与已完成事实分别保留。靠新路返回取扣仍须在固定眼近身、腾手、确认渠内无人后实际操作。
- 当前通用换图会把跟随的许照放在玩家 (+45,+40)，两处候选点均已额外检查该站位。不能为新路挪旧 NPC 初始位置；若正式新地图改变跟随政策，应另核实际落点。
- 当前通用换图还会取目标图的首个静息实体作为 `lastSafe`。旧渠、溪道仍有各自原静息点；正式旧窑不能直接套用“必有可用静息点”的假设，把尚未借到的棚角当已获许可。此处仅指出接入边界，不在本稿增设休息奖励。
