# 背墙旧窑：0.6 隔离白盒技术审查

2026-09-11。只读核对后的入口建议，未实现、未跑白盒、未认可地图可玩性。范围仅为 [ADVENTURE_060](ADVENTURE_060.md) 已定局面的技术落地；0.5 正在完整发行验证，不能把本稿写成新章发布事实。根代理已另建 `.worktrees/kiln-060`，后续实现应在该隔离分支进行。

## 最小入口：独立页面、复用 home 槽位

建议新分支仅新增 `whitebox.html`、`src/whitebox/kiln-060.ts`、`src/whitebox/kiln-060-content.ts`；页面直接导入现有 `model.ts` 的 `createGame / act / tick / previewCast / previewPullMove`，不导入正式 `main.ts`、场景渲染器或存档 UI。现有 Vite 可直接服务这个 HTML，无须改生产入口、`SceneId` 或构建配置；正式单入口构建不会自动把另一 HTML 加入发行。需要独立发布白盒时再显式处理，当前不发布。

在此页面自己的模块环境中，将 `SCENES.home` 赋为 `id:'home'` 的白盒 `SceneDefinition`，再调用 `createGame(profile)`。将生成的 `worlds.home` 收敛为候选实体的独立副本，设每个实体的 `homeX/homeY`；保留其余世界和三个章节的初始未接状态。初态选择只允许可见的普通/零灵力处境，体力与敌人布局相同；重新选择必须整局重开，不在进行中改资源或敌情。

- `contracts.ts` 的 `SceneId`、`GameState.worlds`、`SceneDefinition` 均限定现有五图；强插 `kiln` 会波及存档、内容清单和表现。借用槽位只限这一独立页面，不能进入正式游戏页面后执行替换。
- `home` 在 `stepTick / enemyTick` 没有地形战斗特例，适合空白局面；不要放 `tao / xu / table / lamp / board / basket / gate` 等旧任务实体或操作旧对话。
- `workshop` 的 `enemyTick` 在玩家 `x>1200` 时禁止敌人看见玩家，会制造假安全区。
- `crossing` 的 `stepTick` 无条件读取 `ridge_rock_source.state`；删掉旧实体会直接报错，保留又引入固定落石触发带。它比 `home` 多一层不必要的兼容条件。
- `creek / canal` 有落石、平台或水区规则，不选。新增通用关卡注册器也不属于本次白盒需要。

白盒只转发真实点击、键盘、触屏产生的 `GameAction` 和方向向量；调用 `tick(s,dt,input)` 推进。观察接口返回副本，仅展示位置、敌方 `state / data.lastX / lastY / seen / attack`、事件和资源。出口是地面边界标记，白盒在实际进入东端范围、再实际回到西端时写自己的观察记录 `eastReached / returned`，不写 `GameState.flags`，不调用 `changeScene`，不宣称已接通旧地图。

正式 `objective()` 会返回石驿旧待办，不供白盒使用。白盒说明仅陈述操作和这次要观测的空间结果，不添加新剧情约定、任务完成或奖励。第一切片不放杜芹 NPC，借还关系另有生产模型验证，不能拿“把屏拖回原处”假充人物已经认可。

## 一套可直接摆放的几何初值

以下是静态候选，不是已验证路线；根代理可用已有更合适的局部几何替换。地图 `1400×1000`，矩形统一写左上角与宽高；实体统一写中心。地面仅用 `floor/path/stone`，不要把墙或屏包进 `water` 地面，因为当前射线与射弹均排除被判定为水区的矩形。

| 项目 | 坐标或矩形 | 用途与静态约束 |
|---|---|---|
| 外围上/下墙 | `(80,80,1240,40)` / `(80,880,1240,40)` | 限制外侧绕行，不能画成可穿越道路 |
| 外围左/右墙 | `(80,120,40,760)` / `(1280,120,40,760)` | 西、东标记在围墙内侧，当前只是白盒端点 |
| 第一窑墙 | `(500,220,60,380)` | 墙底 `y=600`；初始西院被墙背遮住 |
| 第二窑墙 | `(900,420,60,340)` | 墙底 `y=760`；须从上侧或下侧真实绕过 |
| 西端/出生 | `(180,480)`，到达半径 `60` | 不靠静息恢复制造普通与零灵力测试的差别 |
| 东端 | `(1220,540)`，到达半径 `60` | 与第二名敌人初位约 `273`，不把端点放进点击寻路的 `145` 威胁禁入半径 |
| 挡屏 | `(500,640)`，`100×40` | `id/type:'shield_board'`，`movable:true, solid:true, flammable:true, state:'idle'` |
| 第一散修 | `(710,640)`，`40×60` | `kind:'enemy', type:'raider', hp:3, state:'idle'` |
| 第二散修 | `(1090,300)`，`40×60` | 同类同参数，不加巡逻、属性或第三名敌人 |

两名敌人均明确 `homeX/homeY`，`data={lastX:x,lastY:y,seen:0,attack:0}`。不要留出模型未初始化的搜索目标 `(0,0)`。

可先核一处明确反例：玩家 `(420,640)` 到第一散修距离 `290`，射线穿过屏的 `x=450..550,y=620..660`；挪屏后同点失去遮蔽。玩家绕到 `(420,700)`，射线从屏下侧经过，长度约 `296`，在普通火球范围内。把屏移到 `(620,700)` 的中心路径在第一墙下方，移动约 `134`，足以触发首次落物声；第一敌人距落点约 `108`，第二敌人约 `617`，初态不会把两者同时引来。杜芹未来站位/目睹条件不在这些距离中暗算成立。

`free()` 的人物膨胀为 `17`。第一墙上方净间距 `100`，第二墙下方净间距 `120`，扣除双方膨胀后分别余 `66/86`，能容纳 `pathForActor` 的 `40` 网格行；屏与第一墙之间只有 `20`，本来就不能挤过去，必须绕屏。第一散修距墙和屏均不重叠，第二散修也不在任何障碍内。上述只证明基础尺寸没有先天相交，不证明两敌移动后仍能零资源走通。

## 原有规则可直接调用到什么程度

| 规则 | 真实入口 / 函数 | 可用事实与界限 |
|---|---|---|
| 步行 | `act({type:'move',point})`；`tick(s,dt,input)` | 点击使用 `pathForActor`，方向输入使用 `moveBody`；默认速度 `160`，牵物时 `85`。两者都需测，不能拿键盘通过证明点击同样能到。 |
| 牵屏 | `previewCast` → `act({type:'cast',spell:'pull',targetId:'shield_board',point})`；随后 `act(move)` 调整落点 | 普通范围 `300`、长牵 `500`，首次耗 `1` 灵力；物件速度 `220`；牵着物件时点击移动的是物件，走人要用方向键或先放下。 |
| 落物引敌 | `act({type:'release'})` → `release` | 仅硬编码 `decoy/shield_board/boat/board` 支持；离 `home` 超过 `70` 后首次放下，引动 `550` 内敌人搜索实际落点，写 `noiseUsed`。无声音视线判断；后来看到玩家会更新末见位置。 |
| 施火 | `previewCast` → `act({type:'cast',spell:'flame',targetId,point})` | 范围 `400`、耗 `1`、准备 `.5s`、冷却从起手算 `1.5s`；直接选屏会忽略其自身的预览遮挡，但实际射弹仍击中屏面。隔屏选敌通常在预览即被拒绝；不能把未发射说成撞击实证。 |
| 射弹与烧毁 | `spawnProjectile / advanceProjectile / segmentRectEntry / flameEntityHit / projectileTick` | 已有连续首碰、出生偏移检测，玩家速度 `420`、寿命 `.92s`；敌弹 `260`、寿命 `1.6s`。可燃屏点燃后仍实心，`stepTick` 在 `12s` 后设 `burned`，`rectangles` 才移除其碰撞。敌弹不会点燃屏。 |
| 护符 | `act({type:'cast',spell:'ward',point})` | 耗 `1`、朝向由瞄准决定、维持 `6s`；前方一次拦截消耗护符，侧后仍能受击。复用原输入与表现反馈，不新增移动盾墙。 |
| 散修 | `enemyTick / moveBody` | 可见距离 `<300`；警觉 `1s`，末见记忆 `3s`；攻击累计 `>1s` 提示，`2s` 发弹。距离 `>240` 靠近；近处看到护符侧移。只有直接转向与沿轴滑动，没有通用绕墙寻路。 |

屏必须沿用 `shield_board` 而非 `board`：后者会触发淋药、改尺寸并读取 `basket`。未来正式第六图可以保留这个按图唯一 ID；若改名，须显式补最小声响能力，不能只给文案。

## 不可隐去的风险与白盒判据

1. **搬屏只检中心。** `pullPlacementReason` 以 `free(point,12,target.id)` 检查中心，再检查中心移动射线；实际 `100×40` 屏角未参与沿途扫掠。候选落点须让整块屏避墙，实机刻意尝试贴角。若角穿墙影响取舍，记录为规则缺口，不能用美术盖住；本审查不修改它。
2. **留势不是可依赖遮挡。** `held` 被 `rectangles` 排除；本局的截弹证据必须用落地屏，不能凭悬屏画面声称受保护。
3. **点击会主动避敌。** `pathForActor` 由安全位置出发时避开可见敌人的 `145` 范围。若鼠标走不过而键盘能通过，需要报告实际拒绝和可用走法；不能强行传送或改敌情补过。
4. **宽绕行可能过于无条件安全。** 静态通路存在不等于压力成立；记录两敌警觉、首发与暴露时长。若四种处境都能闭眼沿同一路顺走，按已定设计局部调整墙角/站位，必要减至一敌，不增伤害或新系统。
5. **不使用正式存档或正式重试。** `restore` 校验完整五图实体清单；白盒删掉家中生活实体后不再是合法进度档。`act(retry/retreat)` 还会回满体力灵力。白盒重开调用初态工厂，保留输入/观察证据，零灵力重开仍为零；正式处境重试、烧毁持久性、借还事实及跨图出口必须在生产集成后另验。
6. **移动和燃烧共用 state。** `act(pull)` 会把实体改为 `pulled`，`release` 写回 `idle`；这会中断正在燃烧的可移动屏状态，烧毁实体也未被 `interactable` 排除。烧后再牵可能恢复实心；这是旧干草不可移动时未暴露的组合缺口。白盒必须记录该边界，不能宣称“永久烧毁”已由现有规则完全保证。

首轮只交付同一初态下的四条真实输入轨迹：留屏换角度、挪屏并归位、烧屏后重走、零灵力通过并返回。每条记录实际端点进入、血/灵力、屏状态/位置、敌方末见位置、首碰事件及是否借暂停中断；不注入完成。至少一条射弹须在已经发出后真实撞到固定墙或落地屏，补足“预览拒绝/敌人没起手”无法证明的截弹事实。

静态阶段到此为止。移动屏角、烧毁后再牵、敌人卡墙、手机点选和暴露压力都是后续白盒观测项；本文件不为它们给出通过结论，也不扩大为新系统或生产美术计划。
