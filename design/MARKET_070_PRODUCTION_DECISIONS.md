# 0.7 小集：三项生产实现建议

2026-09-11。仅收敛 [STATE_CONTRACT_DRAFT](MARKET_070_STATE_CONTRACT_DRAFT.md) 的三个有限问题，供根代理写实施计划；不批准生产、不代表实测。当前第三布局候选沈砚脚点为 **(470,380)**，北口仍 **(1140,240)**，L墙维持当前白盒尺寸；此前草案的摊前(470,440)不能作为生产NPC原位。根代理正在运行真实浏览器，本稿不改运行代码、旧文档或资产。

统一入口前置仍为 `journey.stage === 'complete'`，独行完成有效。旧渠、旧窑和首章事实不借本章改写。以下建议不增加全局同行调度器、探路成就、数值奖励或新恢复系统。

## 1. 方向位保留，纸图每条巷只添一次

**建议采用：** 状态保留 `through[public/private][westToEast/eastToWest]` 和同结构 `reported`；纸图只根据每路是否至少有一个已报告方向，显示一条对应巷道笔迹。方向的差别放在桌边短句中，第二方向不再叠一张纸、不重画同一路、不弹奖励。

示例：首次报告私巷西到东，文字为“我从石渡那头进集，走私巷到了旧渠”；后来真实反向通过并报告，补一句“从旧渠回石渡，这条私巷也亲自走过了”。公共巷另有自己的真实笔迹；只走其中一条时，另一条仍不添。两向历史都成立不能被称为“同一趟往返”，本章不增加该成就。

报告选项仅在真实桌边近身、当前对白有效且 `through - reported` 非空时出现。一次选项可提交当时所有未说明方向，避免重复点四次；说完只追加相应 reported 位。初次归家、自动保存、再次看图或许照在旁不会提交它们。重复交谈改读当前已报告事实，没有领取按钮或 rewardClaimed 字段。

同端退出不加永久探索账：完整局部穿巷后又回同一入口，只在当前事件中如实说“绕过巷道，又折回原口”，清本次片段，不写对端 through、不报告成穿出另一端。已存在的长期 through/reported不动。半截探路同样只清当前片段。这样不增加第二套“见过/探过/走通”清单；若日后确有消费者，再独立设计，不预存无用字段。

现有接入位置：

- `model.ts` 的 `choose`（约242行）已有生活/旧渠/同行的有界处理模式，适合新增市场报告的近身、选项和差集验证。
- `scene.ts` 约603行的桌案渲染已调用 `drawCanalHomeRecord` 与 `drawJourneyHomeRecord`；新增小图装饰应读取 reported 的每路并集。保持纸签在真实桌面内，不加常驻任务面板。
- `journey-art.ts` 的 `drawJourneyHomeRecord` 展示已有纸签尺寸/定位做法。可借布局，不借 `recordedShared` 当市场完成或共同笔迹。
- `save.ts` 新章验证必须约束 `reported ⊆ through`；不会从纸图画面或当前出口位置倒填状态。

## 2. 用新图许照实体表达在场，留图等待有明确归属

**建议采用：** 新图增加一个 `xu_market`、type=`xu` 的真实人物实体，沿用已有形象。初态 state=`hidden` 表示不在小集；实际随行进图才放到入口附近并显示。可见时实体位置/朝向和状态就是在场事实，不另加 `market.companionStage` 或第二个坐标账本。

| 实际行为 | 新图实体及既有关系应如何变化 |
|---|---|
| 首次进图，原状态并非following | xu_market保持hidden，原地图许照不搬来。 |
| 已经following，实际进图 | 核对有限可站脚点后显示xu_market，随后真实行走。仅接受原有同行约定，不补共同穿巷。 |
| 小集近身选择“在这里等我” | 保留当前位置，state=waiting、沿用全局waiting；不走向旧图lastSafe坐标。 |
| 玩家离开，许照在小集等候 | xu_market保持可见状态与脚点，离图不tick；玩家回来可在原处实际重新交谈。 |
| 玩家与她按既有following政策一起实际离开 | 清除新图在场：xu_market设hidden；目标图沿已有同伴语义放到合法入口脚点。不能同时留下一个小集等候者。 |
| 先前留在小集，玩家回来但并未重新邀请 | 保留等待脚点，不因玩家出生在北口就把她吸到北口。 |

“她留在小集”必须对旧图副本有一个**有界互斥例外**，否则玩家到家会见到另一个许照：当 `scene !== market` 且 `xu_market.state !== hidden` 时，说明她仍实际留在小集。旧图许照副本不显示、不参加nearby/交互、不推进跟随；不修改旧副本保存的坐标与旧任务账本。只集中提供一个依赖市场实体在场的可用性判断，供渲染、交互与NPC更新共同消费。返回小集接上她并一起离开后，这个例外自然消失。不要为此重构每张旧图的人物驻留系统。

该表示法的必要不变量：图外若xu_market仍在场，全局不应是following；图内xu_market隐藏时不能让普通companionTick把她改成waiting而凭空出现。新图refused/sheltered时，已经在场者留在实际脚点等待，未在场者保持hidden；不把旧地图 `lastSafe.point` 当新图坐标。旧任务引发的关系变化仍保留，局部特例只防止跨图坐标误用。

现有具体风险与接入点：

- `model.ts:602` 的 `companionTick` 当前取第一个type=xu，不过滤hidden；新图必须先应用在场判断。following分支已有真实威胁、视线和寻路，可复用。
- 同函数约619行的refused/sheltered分支会使用lastSafe.point移动，新图没有静息点，不能直接套用。
- `model.ts` 的 `choose('wait')` 当前文案在非旧渠地图写“到溪道会合”；小集应有局部“在这里等我”文本并保持原位。`choose('invite')` 仍需当前真实可见NPC与近身对白。
- `interactable/nearbyEntity/canInteract`（约131–137行）、`scene.ts` 的实体可见/渲染入口、`changeScene`（约290行）的跟随放置，需要共同遵守上述同一个市场在场例外，不能只藏画面却留下隐形交谈目标。
- `save.ts` 新市场实体验证保存hidden/等待/实际位置及合法关系组合；迁移仅新增hidden实例，不凭旧档following推断从未来过的小集已有许照。

有限入口落点建议沿已核对候选，不新建传送机制：

| 入图侧 | 玩家主候选 | 同行优先候选 | 一个同入口备用候选 |
|---|---|---|---|
| 小集西侧 | (360,760) | (405,800) | (315,800) |
| 小集北侧 | (1030,220) | (1075,260) | (990,240) |
| 小集出北口到旧渠 | (990,350) | (1035,390) | 继续用原旧渠安全放置审查；本稿不另换点。 |

北侧主候选及(990,240)来自先前真实free/LOS局部探测；西侧备用仅静态建议，尚未实走。生产时按实际free、目标场景实体包络及人物间距离选第一个成立候选，候选全部在同一入口旁。若无候选成立，不先提交穿图再强塞人物；允许玩家取消这次出图，或明确选择她留在当前图，后者是一次真实等待约定，不偷偷把following改掉。敌人来向需用实际状态验证，L墙不提供全向无敌。

上述只证明谁在场，不增加市场共同见证位。不得写旧 `sharedInspect/sharedVerify/recordedShared`，也不把一次 (+45,+40) 放置说成她亲自走过了两条巷道。

## 3. 采用既有检查点，只在真实事实边界更新

现有 `model.ts:34` 的 `checkpoint` 克隆整个世界，内层checkpoint=null，并清待办、对白与暂停；`snapshot` 则保留完整当下状态。二者用途不同。**建议本章只在下表节点调用原checkpoint，不按NPC每帧移动更新。**

| 时点 | 保存的真实状态与理由 |
|---|---|
| 实际进入小集 | 在玩家/同行已合法落地、entry来源已写、空visit已建后，由既有changeScene末尾保存；重试有真实入图来源。 |
| 有效交换成立 | 关闭对白、写exchanged后保存；门仍closed，沈砚仍在实际位置。重试不撤销已当面作出的约定，也不白得开门。 |
| 门第一次实际触闩打开 | door=open和solid同步后保存一次，保留NPC当时脚点；重试后门继续开，NPC仍须实际侧让/返摊。不是一选择同意就保存open。 |
| 明确约定在小集等候或重新邀请 | 关系与在场表示已一致后保存，避免重试把“她在这里等我”恢复成隐形跟随。沿用原对话，不新增奖励或检查点按钮。 |
| 任一端实际成功离开 | 先按本次入口与实走方向提交through或判同端折返，清visit并处理同伴在场，再由既有changeScene末尾保存目标图。 |
| 桌边有效报告 | reported差集写入、对白结束后保存一次；再次读图不写相同检查点。 |

门开检查点应在本tick的真实规则更新和片段观察都完成后写，避免同一tick玩家刚跨过横截面却漏存片段。NPC可位于移步途中，这不是非法存档，也不能在恢复时补走剩余路。当前第三布局原位应取 (470,380)，不能沿用早期草案强制回(470,440)。

**retry：沿用还原检查点，不能混入当前世界的市场成果。** `model.ts:414–426` 当前restore整个checkpoint，并按已有规则恢复体力4、灵力6、清败退/暂停/对白/待办/弹体/路径。新章不额外加资源，也不把这套既有失败恢复称为“零资源始终不变”。exchange、door、NPC、当前visit与同伴在场全部取检查点的一致世界。检查点以后牵筐、燃烧或敌人位移可能回退；文案不得说retry保留检查点之后所有发生过的事。

**retreat：保留已成立的世界事实，放弃尚未完成的当前visit。** 该分支不走普通changeScene；需在当前世界克隆前执行小集的有界撤出处理：清visit、不提交through、不报告，保留exchanged/door/NPC脚点、既有through/reported与物件后果。following离开按已存在的撤退语义处理可见同伴，目标安全处若有许照实体则使用其真实合法候选；已明确留在小集的等待者继续留在原处。若安全处无许照实体，不凭空增加副本：保留既有关系，但不得在界面说她已和玩家在同一处，本章共同见证仍为空。

继续执行现有 `journeyAbandonRun / release / lifeBeforeExit / canalBeforeExit`，不得绕过旧渠支持关系和工序中断。现有retreat还会将当前图未退开/未和平敌人按checkpoint重置，这属于原失败语义；不能声称它完整冻结所有敌情。沈砚是NPC，不进入敌人重置循环，不能借此将她瞬移回摊。

当前retreat最后仍保留原 `source checkpoint`；建议保留这一行为，不悄悄改为另建“回家检查点”。因此外层世界可在安全处、visit为空，而内层恢复点仍在小集、有其当时合法visit。之后真正执行retry会回到该处境，二者必须独立验证，不把外层事实复制到内层使其看似一致。新的实际出图、报告或静息仍会按既有代码更新检查点。

新图无rest，`changeScene`仅在找到目标图可见rest时更新lastSafe（约292行）；进小集保留之前真实安全处。`save.ts:204–212` 已分别restore外层和唯一一层checkpoint，继续按各自版本严格迁移；不允许市场lastSafe指向新牌、门或未获许可的坐垫。

## 交给实施计划的有限核对

这三项建议可用少量有意义边界验证：反向入图不补正向、同端折返不加永久账、反向报告不重复画纸/领奖；许照首次未在场不出现、留图等待后旧图不出另一个可交谈副本、从北口同行不擦L墙；交换后retry门仍未开、实际开门后retry保留open、retreat不把visit算through、外安全处/内小集检查点各自合法。相关源码未在本稿修改，这些是后续需要取得的证据，不是已通过结果。
