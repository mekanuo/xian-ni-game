# 0.7 小集生产前状态合同草案

2026-09-11。以 [ADVENTURE_070](ADVENTURE_070.md)、已由根代理修正门槛的 [CONNECTION_REVIEW](MARKET_070_CONNECTION_REVIEW.md)、真实 [save.ts](../src/game/save.ts)、[model.ts](../src/game/model.ts) 与现有旧渠/同行/旧窑逻辑为依据。仅整理生产前合同，不批准生产、不代表实测，也不修改白盒或正式代码。0.6已发布来源为 `19dada6`，本稿接手时其公网检查仍运行，现已通过；0.7首轮白盒实际北返已失败，正在修正几何，本文仍不是生产批准。

## 已锁边界

所有进入小集的既有地图出口使用同一前置：**`journey.stage === 'complete'`**，包括独行认路完成，不要求 `recordedShared`、许照正在跟随、旧窑借还或棚角许可。该前置本来承接旧渠完成。新出口隐藏/显示和实际互动必须同时服从门槛，不能只在画面隐藏。

旧档中 `canal.stage === 'unaccepted'` 不能身处旧渠，也不能以旧渠为 `lastSafe`；这条现有不变量保持。连接研究的未接任务、四水态组合仅是几何或拒绝越权的压力前提，不能拿它们说明正常进度能跳过旧渠、认路回驿直接进入小集。不得通过切图自动接下口信。

生产小集必须使用独立场景身份，不继续把白盒的 `home` 槽位、公开普通/零灵力及有/无消息选择当成正式档。正式信息资格来自玩家已有真实旧窑穿行历史；灵力、手法、敌情都沿正式当前状态。新图不赠资源、重试次数或静息点。

## 最少必要事实

以下为字段职责草案，命名与编码可在实施计划中收敛。仅当存在明确消费者时才增加字段；不引入好感、履约队列、离线计时或无限行程日志。

| 事实 | 最小存放处 | 作用与限制 |
|---|---|---|
| 真实旧窑路况可供交换 | 读取既有 `kiln.crossed.west/east` | 至少一次真实跨窑是信息来源；不另存可被修改的 `informed`。确切对白按已走方向表达，不暗示杜芹作证。 |
| 消息已当面交换 | `market.exchanged: boolean` | 只说明沈砚听过口述并答应开门，不代表木门已开或任何巷道走完。 |
| 门闭合/打开 | 门实体 `state: closed/open` | 唯一门事实；运行中 `solid` 由它派生。门打开以后不重锁。 |
| 沈砚的实际位置、朝向与姿态 | 当前地图 NPC 实体 | 支持未起步、走到半途、见敌停步、到闩边、实际侧让、回摊。无需再存重复的“还欠一次开门”。 |
| 当前一次入图来源 | `market.visit: null \| { entry, ... }`，`entry = crossing/canal` | 只有真实换入小集才产生；身处小集必须有，离开后清空。不能由当前位置猜入口。 |
| 正在穿巷的片段 | `visit.transit: null \| { route, from }` | route 为 public/private，from 为 west/east；只保留连续身体线段真实进入对应横截面的事实。 |
| 本次入图内确实完整穿过的通道与方向 | `visit.passed`，每路两个方向位 | 东西完整通过分别记录；进半截退出不算。一次入图可实际走通多条。 |
| 已由对端真实离场提交的穿图经历 | `market.through`，每路两个方向位 | west→east 对应石渡来、小集北口去旧渠；east→west 对应旧渠来、原口去石渡。只由实际跨图提交。 |
| 已回驿当面说明的经历 | `market.reported`，同结构且为 through 的子集 | 只在已有桌边近身对白中提交未说明部分。到家、打开山道图或读档不自动报告。 |

到访本身可复用现有 `flags.visited_market`，不要同时存一个等价 `visited`。门状态与NPC实体不复制进市场账本。当前是否有可见威胁、NPC下一段往哪走、是否可交换、有哪些可报告项均按现有事实派生，不保存“现在安全”或“已经收到奖励”。

本草案建议把双向通行作为两个真实方向位保存；画面可以只在对应公共/私巷添一次底图，再用有限文字说明返向行走，不能因反向通过再发一套相同奖励。若最后产品只需要无方向的纸图，方向位仍用于正确归因，是否只显示一句返程回响可后定。

## 从哪边来、走过什么、从哪边离开

空间仍是单层：石渡连小集西侧原口，旧渠连小集东侧的北口。北口的地理名称不意味着另一个楼层；方向归因使用东西横截面，不用屏幕上下或新牌箭头猜。

连续观察采用实际货屋与玩家半径形成的边界：当前白盒横截面 **x523–797**，私巷 **y397–483**、公共巷 **y797–903**。正式几何若调整，必须同步真实墙体与观察边界，不能保留一条看不见的资格线。连续在同一通行带内从一侧完整穿到另一侧才写 `visit.passed[route][direction]`；从中间开始、同侧探回、绕带外折返不能补造。反向通过按反向位记录，不抹去本次先前实走的另一个方向。

| 实际过程 | 出图时允许新增的穿图经历 |
|---|---|
| 石渡入 → 私巷西到东 → 北口实际切到旧渠 | 私巷 west→east。 |
| 旧渠入 → 公共巷东到西 → 原口实际切到石渡 | 公共巷 east→west；绝不能补西到东。 |
| 石渡入 → 公共巷完整西到东 → 实际走回西侧 → 私巷完整西到东 → 北口离开 | 本次两条 west→east 都可保留；不是由最后选择覆盖先前实走。 |
| 石渡入 → 只探半截私巷 → 完整走公共巷 → 北口离开 | 只有公共巷 west→east。 |
| 旧渠入 → 北口附近停留 → 从同一北口回旧渠 | 同端折返，不新增任何 through。 |
| 旧渠入 → 从东侧探私巷后退回 → 北口回旧渠 | 同端折返，不新增西到东或穿图成果。 |
| 石渡入 → 完整走到东侧后又回原口 → 从原口回石渡 | 本次发生过完整局部穿巷，但没有从另一端穿出；不得称已打通一次石渡到旧渠穿图。 |
| 到达任一标记但尚未实际换图，或暂停时排队点击出口 | 仍只是现场位置/待办，没有提交穿图经历。 |

对端离场只取与 `visit.entry` 对应的方向集合。例如旧渠入图即使又在内部绕了一圈产生 west→east 片段，最后向石渡离开时也只提交本次真实 east→west 集合；不把绕圈中的另一方向伪装成“从石渡来”。退出成功才清空当前 visit；失败的交互、被拒绝的传送和原地关对白都不得清除或结算它。

**局部折返的边界建议：** 同端离场保留已有长期 through/reported、沈砚与门，清本次暂存片段；给出如实的“折回原口”事件。完整局部穿巷后同端返回是否值得另记“探路”文字，是未决的呈现需求；在没有消费者前不另增一套永久探索账本，也不将它当正式穿图报告或奖励。若根代理要求保存这种局部知识，应明确它与 through 的区别后再扩字段。

可以从两端独立开始下一次入图，不要求先回石驿或保持白盒的 `exitRoutes` 跨地图等候。小集已有真实双向连接即可支持各自回路；若产品还要专门承诺“同一趟完整往返”，须增加能够对应去程与返程的事实，不能仅凭两方向历史位都为真就称同一次往返。本草案不新增该成就或承诺。

## 沈砚的承诺如何成为实体动作

1. 只有当前近身、视线成立、对应对白和可用选项真实存在，且信息资格/眼前威胁允许时，交换才写 `exchanged=true`。不接受远程 choice 字符串，不读取已开门状态倒推曾经交换。
2. 交换结束不推进模拟时间。门仍 closed，NPC仍在当时脚点。正常对白冻结世界，关对白保持此前手动暂停；暂停待办恢复后重新检查条件，不能在读取存档或关闭设置时越过检查。
3. 小集处于当前运行场景、时间真实增加时，NPC按现有真实视线/碰撞移步；眼前威胁令未完成动作停在当前合法位置，消失后继续。不用冷却倒数代替走到闩边。
4. 到闩侧满足实际接触阈值才改门实体为 open，立即同步碰撞；之后实际侧让并返摊。返位也可因当前可见威胁停/续，已经打开的门不重锁。门开后再次交谈的文字必须承认门已开，再说明当前来向。
5. 离开小集时保留交换、门、沈砚位置/朝向，停止本图 tick；既不瞬移回摊，也不离线走完开门。返图/读档先呈现同一现场，恢复运行后才重新判断当前威胁并继续。保存的 leading/waiting 是最后姿态，不能当作离图期间走过的距离。

草案中的位置验证需要覆盖当前白盒已用的有限真实走线：摊前→闩侧，以及门开后的上侧让位→返摊。允许沿线中间停步，拒绝任意越墙坐标或“未交换却已在返位途中”。坐标不应强制等于某一个端点而使有效途中存档无法恢复。门 open 必须有 exchanged；closed 与 solid=true、open 与 solid=false 需一致。导入不能将矛盾档悄悄修成开门成功，运行时派生属性也不能成为第二个独立开门凭据。

## 回驿说明与重复行为

报告只消费 `through - reported`，需在真实石驿桌边近身、当前报告对白/选项有效时执行。先前已报告的位保持，新增说明只补对应实际路线及方向；站在别处、切回石驿、恢复页面、重复选择同一话题均不补未走部分。

纸图、对白和人物记忆都读取同一报告结果。沈砚只知道自己当面听到的旧窑路况和眼前开门，陶七只在玩家说明后知道这次小集走法。许照是否跟随不替代报告，也不自动增加共同笔迹。没有新的数值奖励，因此无需另设 rewardClaimed；若将来确有一次性物品或设施，必须先确定设计消费者，再增加与真实交付一一对应的事实。

## 许照的可见在场与安全落点

新图不能只有 `flags.companion='following'` 而没有可见人物，离开后又把她传送到旧渠并宣称同行。生产候选应使用新图独立的许照实体，沿用已有形象与实际朝向/暂停冻结，不用第二个普通NPC冒充。

- **已经 following 时入图：** 按已存在的场景同行语义放到真实可站位置，随后用原 NPC 行走/视线规则；不额外发出同意同行。西侧玩家到达候选 (360,760) 对应 (+45,+40) 为 **(405,800)**；北侧玩家 (1140,365) 对应 **(1185,405)**。出图到旧渠的玩家 (990,350) 对应 **(1035,390)**。这些是候选脚点，北侧敌人可能已迁移，固定偏移不是所有旧状态都安全的证明。
- **waiting/refused/sheltered 或尚未同意时：** 不把旧图许照挪来新图，不在入口凭空出现同伴。若她此前真实留在小集，保留小集中的实际位置与等待表现；不能单靠当前全局关系值推断她当时留在哪张图。
- **最少可见性事实：** 优先让新图许照实体自身的 hidden/现场状态表达是否实际在该图，并保存脚点；只有需要区别“在别处”和“就在这里等待”时才使用这一事实。避免同时新增一套同行章节阶段。与当前每图都有一个许照实体的历史表示法如何衔接，须在生产接入计划中明确，不能靠渲染时根据全局 following 临时显隐完成。
- **安全位置必须真实裁决：** 换图前核对玩家与许照候选脚点的固定/活动遮挡，不将人物放在门板、货屋或彼此重叠处。若固定偏移不成立，用同一入口附近的有限真实可站候选，不能改坐标到地图另一端跳过通道；若没有可成立候选，不先提交穿图后再补救。是否还需按现有危险距离避开敌人，应在真实战斗与入口测试后明确，不赠无敌或清敌。
- 本章尚不承诺新的共同穿巷成绩。可见跟随、到达出口和亲历通道是三件事；禁止直接写旧 `sharedInspect/sharedVerify/recordedShared`，也不以同屏或一次换图作为共同见证。

## 跨图钩子与失败恢复

实际出口动作先做旧前置、目标脚点与本章归因检查；只有换图成功的同一动作才提交 through，并写入新的 visit 或清掉旧 visit。应区分“准备允许换图”和“已经成功切图”，避免当前通用 `changeScene` 的前置钩子中提前写成果、随后失败却保留。

沿用并保留原钩子顺序所承载的后果：`kilnBeforeTravel`、`journeyBeforeExit`、放下牵物、`lifeBeforeExit`、**`canalBeforeExit`**，再实际换场。小集只加自己的有界处理，不跳过旧渠收稳水板、结束工作和离图不计时。小集轻物不跨图携带；其位置、烧毁与敌人退开结果留在原图。

新图不设静息点。现有 `changeScene` 只有找到目标图可见 rest 才更新 lastSafe，应保留进入小集前的有效安全处；不要用 undefined、入口牌或未获许可设施充作恢复点。若玩家败退后使用现有“撤回歇脚处”，需要专门结束当前市场 visit 而不发穿图记录，保留已成立交换与门；不能依赖普通出图钩子，因为现有 retreat 走的是另一条恢复分支。

现有 retry 从 checkpoint 还原整个处境，retreat 则保留多项现时世界事实并调整地点/资源。生产前应明确小集采用哪些 checkpoint 时点，避免真实交换后败退重试恢复到更早未交换档却被描述成承诺仍在。建议至少把有效交换、真实跨图和回驿报告作为可审阅的检查点候选；门边每个tick不写检查点，也不以自动保存代替处境检查点。

## v1–5 与 checkpoint 的严格迁移

现有 schema 为1、revision 为 `return-stone-v1`、contentVersion 为5；新生产内容可候选升级为6，但数字尚未实施。历史“v1”实际以 **缺省 contentVersion** 表示，现有显式数字1不被接受；不得顺手扩大旧版本接受范围。

迁移次序须保留“先验证来源版本、再追加新内容”的方式：

1. 首先按来源 v1–5 的原场景/实体清单和原不变量验证。旧版本若混入 `market` 账本、市场场景、市场出口、市场 lastSafe 或新许照实体，应拒绝，不能先追加后顺便把伪造内容合法化。新实体应像 `initialKilnEntries` 一样与旧清单分开，避免修改共享模板导致旧档突然缺器物。
2. 合法旧档只补新图初态、新出口与空市场账本：未到访、未交换、门 closed、沈砚摊前、当前visit为空、through/reported全空；出口开放只派生于原本已完成的 journey。不凭旧窑消息资格推断“以前来过小集”。新许照不凭旧 following 立即出现在一张从未进入的新图。
3. 保留旧 player/resources/flags/time、暂停、pending、dialogue、projectiles、lastSafe、生活/旧渠/同行/旧窑和全部旧实体，不能为使新图测试方便而归还压扣、复水、移位许照、重置旧敌人或抹掉暂停中的跟随事实。
4. 按新版本完整验证：精确场景与实体集合，无缺项/重复/额外图；市场结构、入口门槛、固定几何、门状态与solid一致、NPC合法途中位置、scene与visit一致、路线方向枚举和reported⊆through均成立。不能从玩家当前站在东侧补出west→east历史，也不能仅看布尔组合就声称验证器证明了真实输入——验证器约束格式与因果一致，游玩证据另取。
5. 外层世界与 checkpoint **各自按自己的版本独立迁移**，允许外新内旧或外旧内合法新；不把外层市场成果复制到旧恢复点。继续只允许一层checkpoint字符串，内层checkpoint必须null，大小限制与畸形JSON拒绝保持，不能递归读取任意层级。
6. 当前 snapshot 保存暂停/对白/待办原貌；现有 checkpoint 创建函数有意清 dialogue/pending、设 paused=false。不得在迁移时再次应用创建checkpoint的清理逻辑。恢复世界本身不推进沈砚、不触闩、不提交出图；导入UI保持暂停的现有语义不变，恢复运行后待办仍走真实动作裁决。

必须保留的反向拒绝例：旧版本混入新图；journey未完成却在小集；canal未接却在旧渠/旧渠lastSafe；未交换但门开；门open而solid；NPC越墙或未交换却离摊；小集内visit缺失/图外visit残留；reported含未提交方向；只凭北侧出生伪造西向东通过；外层合法但checkpoint矛盾；双层checkpoint。不能用默认重置坏字段的方式“修复”这些档。

## 生产前仍须收敛的少量问题

- 双向方向位与纸图的最小呈现：反向补走是否只补一句说明，以及同端离场的完整局部探路是否值得额外长期记录。任何取舍都不能把同端折返说成对端穿图。
- 新图许照“实际在场/留在别处”的表示与留图等待行为；固定 (+45,+40) 在已迁移敌情下的安全落点策略。先验证有限候选，不扩成全局同行重构。
- 本章检查点具体时点，以及 retry/retreat 分支如何保持承诺和清除未完成visit。须与既有失败恢复语义一起审阅，不假定普通出口钩子覆盖所有离图。

入口门槛、旧渠未接不得入图、不得离线履约、真实方向归因与不赠共同见证均不是待重新询问事项。上述只是本生产候选需要落实的有限实现合同；本文件没有运行测试、浏览器或存档迁移，不将静态方案写成已经成立的体验。
