# 山外短暂结伴：有界概念审查

2026-09-12。仅审查根代理提出的一个候选：玩家为自己的目的离开石驿环网，与另一位同阶原创行路者暂时同行；对方根据实际敌情选位并施放一发有限资源的火焰球；玩家可利用、配合或拒绝这次协作；抵达真实山外停留处后各自决定去留。本文不批准白盒或生产，不修改实现。0.8 完整验收 R4 仍优先。

**判断：这个候选已足够区别现有内容，值得收敛一份局部空间与人物合同；此时不因“又要经过一段路”判否。** 新意在于另一位有自己目的和有限本领的修士，亲手改变了双方眼前的交战条件，玩家必须决定怎样接住这一变化。他不是跟随装饰、开门服务或考官。是否真正成立，主要看这一发是否产生可用的窗口，而不是看目的地能否再提供一项新机关。

## 审查口径与上一稿的修正

沿用 game-concept 的因果权、结算权和最小反例方法；产品、来源与总方向读取入口见 [上一份诊断](OUTBOUND_090_PLAYER_PROMISE.md)。本次补读 [0.5 同行设计](COMPANION_050.md)、[0.8 练场设计](SPAR_080_GAME_DESIGN.md)，静态核对 model 的敌人、火球与首撞实现，不运行测试或浏览器，不重读原作。

上一稿把“每个目的地必须有可重复的施术实践、必须改变使用条件”写成了该局部目的地的硬门槛，范围过严。**有参与量的完整出行可以以探索、发现、景观和普通叙事回报收束；目的地不必再造物理谜题，也不必可刷。** 本审查修正该解释，不改上一份独占已交付文档。仍保留的是：需要真正到达、可以停留与自己返回，不能用地图标题或未制作的未来承诺代替抵达。

人物、行程、停留处均为 open 原创；基础控物、有限施术、求援与各有去处沿 SOURCE_SCOPE／SOURCE_BIBLE 的 adaptable 结构。没有王林功绩、宗门裁决权、新境界、第四术法或新货币。

## 与旧章的区别到底在哪里

| 已有内容 | 已经做到的事 | 本候选必须多出的因果 |
| --- | --- | --- |
| 0.5 工棚回程 | 许照已会主动领路、等候和拒绝冒险，并非纯被动跟随 | 临时同行者自己选位、消耗自己的灵力、向共同威胁出手；双方都改变条件，不能只给许照领路动画加一发特效 |
| 0.6 旧窑 | 玩家改变掩体／敌情，杜芹按真实借还回应 | 同行者不是提供一件屏后等归还的人；其站位、判断与出手结果进入当下通行选择 |
| 0.7 小集 | 沈砚按可见危险停／续并真正开门 | 新人物不出售一条私路；路不是因接受交换才开放，其一发也不等于门闩状态切换 |
| 0.8 练场 | 闻朔真实换位后向玩家出一手，玩家以移动和护持回应 | 玩家与施术者面向外部威胁，没有固定站圈、回合开始按钮或命中考试；可以不打、先走、配合后分开 |

不要求每种旧动词产生前所未见的效果。同样的火球打断，发生在另一人自主投入有限本钱、玩家决定如何利用的关系中，可以有新的体验。相反，若接受同行以后站着等，他便射死拦路者并宣布通行，实际结构仍是“点人开门”，应判否。

## 最少需要说清的人物意志

1. **他本来就要走。** 开场一句具体去处与当下理由足够，例如只与你同路到某处便转向自己的目的地；不是玩家出现才生成的求救任务。他可以提出结伴，也接受你独行，不扣好感、不封外路。
2. **他只承担有限的一步。** 愿意用一发争取通过机会，不承诺清空道路、追敌到死或陪你往返全图。若仍有灵力但只愿承担一发，应明确是意愿边界；不能把实际还有的灵力谎报为耗尽。若确实只剩一发的资源，发出后就保留这项消耗。
3. **他会判断出手面。** 面前有真实遮挡、射线不成立或退身面被占用时，会换到有限候选位置或暂缓；他不需要最优战斗 AI，更不需要跟随鼠标自动提供最佳解。停步原因应能从眼前物件／敌人看懂。
4. **他有自保与中止权。** 玩家把危险带到他面前，他不能在“等同行”的姿态中无限硬吃攻击或充当不受影响的诱饵。具体采用退向遮蔽、拒绝继续或已有避险式结果可后续选定；不为此预设永久死亡、复杂救援或新伙伴血条系统。
5. **不强迫玩家抓住机会。** 发出后玩家仍可原地观察、绕另一侧或返回。他会为自己的安全收势并去自己可达的位置，不因玩家没踩到一个暗藏窗口就自动敌对。共同抵达与仅同意过同行要分开。

人物只需短段有界行为：商量→自己移动／等可见条件→准备→真实发出或取消→收势／避险→实际抵达后分开。这里是行为说明，不是已选定的数据结构。对话和普通暂停仍冻结整个现场，不能让玩家点对白时他偷偷打完。

## 一发火球至少要保住的真实因果

静态实现支点：[`contracts.ts`](../src/game/contracts.ts) 的 `Projectile` 当前仅有 `owner: player | enemy`；[`model.ts`](../src/game/model.ts) 的 `spawnProjectile`、`advanceProjectile`、`flameEntityHit`、`enemyTick` 已有实际发射偏移首撞、实体／墙碰撞与火球命中打断。**“现有火焰球”不等于友方自主施术已经实现。** 当前 enemy 弹找玩家／许照，player 弹又遍历实体；不能只把 NPC 子弹改成 player，就声称归属、击中对象和敌人认知全正确。这里只列需明确的局部合同，不要求重构全游戏阵营系统。

| 因果环节 | 最低合同 | 应拒绝的捷径 |
| --- | --- | --- |
| 看见与选位 | 此人按自己的实际脚点、可见目标、可达候点选择；知道哪名敌人来自亲见或已经明确收到的信息 | 读取玩家镜头外全图敌情，从安全墙后锁定某人 |
| 起手与资源 | 可见朝向与真实目标一致；何时扣自己的有限灵力、取消是否消耗须统一；真正发射次数有有限上限 | 点同意即扣玩家灵力，或被打断后无限重试免费补弹 |
| 发射与首撞 | 从此人实际位置发出；发射偏移也走碰撞；墙、落地物、可受击对象按最近接触决定结果 | 起手动作对着墙，火球却从墙后生成；约定目标必定受伤 |
| 身份与受击对象 | 明确射者是谁、谁可受伤、谁挡弹；沿既定无友伤方向，不临时引入误杀伙伴 | 射者先撞自己、子弹错误伤玩家、所有友方身体和墙都无条件穿透 |
| 命中／未命中 | 真命中才触发已有抵抗减少、打断和告警；撞墙、落空、提前退场都保留实际结局 | 只要发过一发就让敌人僵住、消失或解除整条路危险 |
| 敌人的回应 | 根据实际可见射者／弹道来向反应，不因友方出手就隔墙得知玩家的位置；是否转向射者须明确 | 仍用“命中来自玩家”处理一切，凭 NPC 的子弹给躲在墙后的玩家加全知仇恨 |
| 余弹与离开 | 暂停冻结，恢复续飞；取消同行不抹掉已发一发；不能以普通切图清弹结算“协作成功” | 接受／拒绝／重新交谈重置灵力，或者离图后离线替双方打完 |

不在本阶段要求玩家必须以护符保护这位新人物。如果将“我挡住反击，让他完成出手”作为推荐做法，就必须证明敌弹会真实威胁该人物、护符在真实方向上截住这一发；目前仅保护许照的特例不能算现成保证。较小版本可先让玩家以护符保护自己的通过，人物用自己的选位自保。

## 玩家可作出的不同选择

同一公开初态下，至少保留以下可理解的方向，不以每条都有专属奖励为条件：

- **短暂结伴，借他的出手通过。** 玩家先选自己准备走的侧面，看他实际换位与起手；真命中形成敌人动作中断后，自己行走或护持穿过。对方消耗一发、玩家保存部分灵力，未退场的威胁仍在。不是“说好一起走”便共同到达。
- **配合改变当前局面。** 玩家可以先引开观察方向、调整自己站位、以护符承担自己的来袭，或者在确有用途时追加现有火球；对方按新敌情决定能否出手。无需强制一套“三术连按”，更不能给友方射击凭空添加长时间硬控来凑流程。
- **独行或中止。** 走自己的实际路线，资源与危险由自己承担；对方不追着玩家施术，也不在离图时替玩家完成共同通行。独行抵达拥有同一目的地的景观和个人发现，共同行程只增加它实际产生的人际内容。

这次参与不需要证明“凡人绝对无法到达”。原创凝气修士的身份通过双方能隔空施术、会保留自身灵力、愿不愿为陌生同路人投入这一发体现。没有人需要失能以显得玩家重要。零资源仍有真实退出，不接受必须买下这位修士服务才能离开；独行完整通路的危险与尺度仍待局部空间合同证明。

## 最大反例：一发究竟是共同过路，还是免费自动开门

**核心反例组是同一局面下，玩家站着不动、直接点前方、先换侧面再利用出手。** 看三个问题：

1. 若玩家不动，NPC 是否独自稳定清场、反复补弹，随后所有人只须走过去？若是，候选退化为代打放行，判否。只等 NPC 一发再主动走过去可以是正当简洁做法；问题不是“等待过”，而是空间选择和有限投入完全无关。
2. 若 NPC 那一发撞在眼前的实际遮挡上，玩家的可用通过条件是否真的不同？若仍照时钟开放安全窗口，说明窗口是脚本门，不是射弹因果，判否。
3. 若这一发命中只造成短暂打断，正常玩家是否来得及从已准备的侧面利用它？若必须在毫无准备时做亚秒反应，或只能靠脚本读取发射帧抓时机，不推荐这个布局。优先让玩家在起手前选择站位、缩小需要跨越的局部距离；不重开 0.8 已否决的主动火球反应考试，不先加长全局硬直。

一个正面证明和上述一组反例足以决定是否值得继续，不在此预填多设备 QA 清单或强制每一种组合都独立通关。若一发既不能让预备好的玩家受益，也不改变双方接近条件，就不能仅用亲切对白宣布“并肩作战”；应搁置这一局面，而不是加成三发、再加一道门或赋予新控制术。

## 目的地可以安静，收益可以是故事与发现

途中已经有空间行动和自主协作，抵达后应允许节奏舒展。最少需要一个玩家可实际走入、辨认并停留的山外地点，一个当前就能发现的具体内容，以及双方在此怎样分开。地点不必设新经营、新能力奖励或第二轮战斗。

“具体发现”可以是从实际眺望面看清此前只听过的山下去路，或听到一位离山者为何选择自己下一站的短谈；这些必须是本次可体验的内容，而不是灰色按钮和“以后有城镇”。景观无需因为玩家走近而改变物理状态，人物正常交谈也不必把每句变成机关。

个人去留可以只是现在多看一会儿、独自走到另一处可达观察面、与对方道别后回驿，或表达以后还想来。**表达想走，不等于已经走到未制作的地方；临时结伴，也不等于得到永久伙伴。** 未同行的人仍能看景、停留和返回，不被剥夺主要目的地内容；同行者只提起实际共同经过／亲眼所见的事，不替玩家补写另一侧的经历。

因此，此候选不必等到找到“目的地可反复使用的物理设施”才有意义。真正的局限仍是目前没有确定地点内容和一次可读的过路局面；这两处要写具体，但不必扩张成另外两章。

## 收束建议

**有条件保留，优先收敛；不判为旧借路换皮，也不批准生产。** 最小下一份合同只需回答：双方这次各去哪里；何时同意及结束短暂合作；NPC 一发的条件／取消／消耗；一个能预先站位利用的真实交战窗口；独行与退出；抵达可见的发现及实际分开。没有必要增加新的术法、敌人种类或大城镇。

本候选的 `player_job` 是为自己寻访而暂与同阶合作的行路修士；`recurring_job_loop` 是判断共同阻力→各自站位并有限投入→按真实结果走或退→抵达后分开；`signature_command` 为 N/A；`resistance_chain` 是有限视线、各自意愿与资源、首撞和有限机会；`advancement_ladder` 是从自己会躲一手，进到能读懂另一人的实际施术、决定怎样与之同行。最后一项是待证明的玩家经验，不是自动“学会协作”存档标记。
