# 0.1.1 手机清晰度、声音与命中反馈

2026-09-09。对应用户反馈：手机打开有像素感、页面不够精细、听不到背景音乐、没有打击效果与打击感。本轮直接修正实际运行代码；[上一轮目标图](QUALITY_REVISION.md)仍是方向参考，不当成实机成果。

## 已实现

- **清晰度**：Canvas 绘制按屏幕像素密度匹配，最高 3 倍并限制总像素预算。原来的 390×844 手机 CSS 视口只绘制 390×844，现在在 DPR 3 下绘制 1170×2532；横屏、旋屏重新计算比例。相机、点击坐标、文字纹理同时适配，避免只扩大画布造成触控错位。
- **场景细节**：四场景的土路、石地、草边、水岸加入按地形裁切的细纹理、铺石、碎石与少量湿痕，地面以 2 倍精度缓存；减少重复竹草列，石堆改碎石边缘，灯盏补灯骨、提环和局部光。归灯后只显示一盏挂灯，去掉旧“松脱”标签。
- **手机界面**：横竖屏分别排列资源、菜单和术法；触控按钮至少 44px，适配安全区。对白时隐藏冲突的动作条与提示，不让操作文字压在选项上。
- **背景音乐**：原创八小节循环旋律、和声、低音与轻回声，进入工棚和石渡时调整节奏。属于程序合成配乐，不冒充录制的真实民族乐器。点击入山等用户手势启声，常驻声音状态/开关，音乐与音效分别调节；后台停止调度，恢复时不爆发补播。
- **战斗反馈**：起术聚光、火球尾迹；命中出现短闪光、冲击环、火屑、目标短退/侧倾及“命中·打断”；受伤有局部闪色和受击动作；挡击有破光与独立声音。微量镜头震动可通过低动效关闭。表现只读取模型事实，不改变伤害或空间碰撞。
- **事件音频**：逐个消费所有新事件，修正同帧“命中”被后续“警觉”等通知覆盖的问题；读档与重开清掉旧特效，不重新播放历史打击。
- **操作连续性**：行走时打开菜单或交谈，结束后继续行走；明确暂停/失焦保留暂停。修订此前必须多按一次继续的操作。

## 证据与边界

权威执行入口 `npm run verify` 包含模型、实际 Chrome WebAudio、同帧事件回归、界面/存档、手机 DPR 与触控/旋屏、真实战斗声画、完整通关与重开。结果以 [verification.json](../qa/verification.json) 为准。

新增证据：`qa/evidence/mobile-render.json`、`mobile-390.png`、`mobile-844.png`、`combat.json`、`combat-hit.png`、`combat-hurt.png`。手机证据为 Chrome 触屏与 DPR 仿真，**不是 iPhone/Android 真机扬声器或 Safari 验收**。音频 RMS 证明有实际输出信号，不证明所有手机的主观响度；打击事件与视觉证据也不等于用户已经认可手感。

本次没有把整套角色换成逐帧手绘动画，没有完成上一轮目标图的全部建筑/角色资产重制，也没有把直角地图拓扑说成完整手绘景片。0.1.1 先交付可辨的清晰度、配乐和即时反馈改进；具体体验由用户继续试玩评价。
