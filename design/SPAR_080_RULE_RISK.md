# 划线切磋 C：最小规则风险审查

2026-09-11。读取 AGENTS/HANDOFF、[C 卡](NEXT_CONTENT_080_CANDIDATES.md#4-概念-c划线切磋赢得一手不压服一个人) 及当前模型、合同、反馈和显示代码。0.7 已发布，碎崖 r1/r2 已归档搁置。本轮仅新增本文；**没有代码、测试、模型回放、浏览器或数值实测**。以下是供根代理选择的有界建议，不覆盖 A/C 的选题状态，也不批准生产。

**判断：C 值得先做一回守线灰盒，但不宜直接实施“两回合、识破旧招、主动逼位”的整张卡。** 最小切片建议先只用步法／护符，证明自愿开始、真实来袭与应对、收手后余弹的完整因果；主动火球留到下一道独立对照。既有散修可复用射击和对护符侧移，不是已有切磋 NPC；零灵力成功和手机可读性仍未成立。

## 1. 可以复用什么，不能冒称已有

| 现有事实与位置 | 本候选用途／限制 |
|---|---|

`Entity.kind='enemy'` 才会走攻击和受火伤逻辑；`type='raider'` 决定既有对手形态。仅把 name 改为闻朔不能近身约战：生产 `scene.pointerDown` 点 enemy 只提醒留意起手，`interactable` 也拒绝 enemy。灰盒需明确自己的有限约战入口；同一实际实体可以有局部交谈适配，不复制一个重叠的 NPC 和敌人，也不以切换 kind 吞掉已发火球的命中。

## 2. 建议收窄为一轮、一种守线约定

第一轮只留一位自愿对手、一块无可燃财物的平地、看得清的练习边线和实际离场位置。玩家先只用步法／护符；主动火球、牵物机关、近战、第二对手、许照护送、第二回合学习或奖励均暂不纳入。火球真实打断已存在，但自愿对手被击中后的收手仍需要单独对照，不能借既有战斗测试直接认定。

根代理应先写清“一回”的结束事实。我建议先试**一发实际来袭及其处理**：守线内避开／真实护符截住；第一实际伤害、越线或主动认输则提前收手。它是验证最小互动，不足以直接宣称已形成可长期练习的完整章。

- 同意与开打分开：近身明确约定，双方身体实际站到各自可站位置后才启用攻击；不因选择同意把人物瞬移到开打点。玩家未就位时不会先挨一发。
- 入局要求玩家 HP≥2；建议对手也至少剩2抵抗，且双方没有在途弹体、未完成的火球起手或牵物。初态资源公开说明，开始、结束均不回血、不回灵力。
- 仅在已实际发射的来袭处理完毕后读取对应结果；时间过去而没有攻击不能自动胜。一次未命中不代表获得了永久属性或掌握全部步法。
- 越过练习边线是停止／退出，边线不是把人关在场内的碰撞墙。退出不封路、不扣奖励；也不把 NPC 因躲护符越线计为玩家自动获胜。
- 更换练习目标、第二回合与重访回应后续再论。当前 raider 不会主动“逼人越线”或评价人的招式，不能只添台词假称会了。

这组约战、就位、有效回合、停止与结果判定全部是 **open／新增局部规则**。现有 `GameState` 没有切磋字段，`GameAction` 没有约战/认输动作；独立灰盒可保留很小的本地回合记录，不扩正式 SceneId、生产存档或泛用伙伴命令。

## 3. 首伤停手能保证什么

现行时序为：每个 `stepTick` 先推进玩家未完成起手，再移动玩家，再执行敌人的起手与发射，之后处理在途射弹，最后才是各章局部 tick。`tick` 会把调用时间拆成不超过0.025秒的小步，但一次外层调用最多可推进1秒。因而“每渲染帧结束看一眼 HP”不等于在首伤时立即停止下一步。

### 单一散修下的有限上界（包含后续火球对照的风险）

- 敌弹寿命1.6秒，速度260；连续射击至少间隔2秒，发射后的24单位偏移也经历首撞检查。没有其他射弹来源、没有预存弹体且没有人为重置攻击计时促发时，正常单一散修不会同时保留前后两发活弹。寿命离散步的最多约0.025秒余量仍小于2秒间隔。
- 若敌弹是第一伤害来源，它命中玩家后 `life=0`，不再继续伤人。及时停止后续攻击，可以让玩家只失1 HP；从2开始保留1，不是无伤。
- 若玩家火球先命中对手，对手之前已经发出的**一发**仍可能命中玩家。因此首伤叫停并不能承诺玩家接下来不会受伤；在上述单来源约束及及时停发条件下，余弹最多再带来一次玩家伤害，HP≥2仍不至于归零。
- 玩家火球从起手时设置1.5秒冷却，0.5秒后发射，在途寿命0.92秒。正常连续发射间隔至少1.5秒，单发寿命即使计入至多0.025秒离散余量仍不超过约0.945秒；因此清空旧弹的合法初态、参数不变且不重置冷却时，**不会有两枚玩家火球同时在途**。这与一概假设“首个命中后还有第二枚已经飞出”不同。
- 但首伤若来自敌弹，玩家可能已有一枚飞出的火，或者 `flags.casting=true` 的未发起手。已飞出的火不能收回；未发起手要停止 `flags.casting`，清除其 `castTime` 待发语义和暂停 `pending` 中的进攻意图，不返还已扣灵力。结算后也要拒绝新的进攻 `cast`，否则下一发仍会正常产生。
- `flameEntityHit` 不把 `peaceful` 当免疫：余火会减抵抗并把对手改回 alert；若当时仅1抵抗便会变 retreated。因此若以后开放火球，双方入局至少2、保留余火碰撞与逐小步停发许可缺一不可。结果文字要承认“收手后先前出手的火才碰到”，不能说一停就毫发无伤。

以上不是安全实测，也不是任意场景保证。必须同时禁止新回合夹带旧弹、另一敌人/落石、燃烧或物件挤压伤害、治疗刷回合、未停的后续施法。对手需要保留至少2抵抗同理，否则“点到”也可能直接将其打到0。

### 最小可靠执行边界

独立 wrapper 可按≤0.025秒逐小步调用真实 `tick`，每步后比较双方实际 HP／抵抗与新事件；发现首伤或本回合停止条件，**在下一小步前**禁止新的起手和发射。不要只在传入1秒的大调用之后处理，不借玩家1秒受击无敌凑“应该不会再伤”。这只是后续实现建议，本轮未写 wrapper。

收手后仍要用真实 projectileTick/首撞继续推进余弹。`peaceful` 可以阻止 enemyTick，但在途玩家火球仍可能通过 `flameEntityHit` 把对手状态改回 alert；因此不能只设置一次 peaceful 就当永久停手。局部回合许可应在每个后续小步约束敌人发起攻击，保留既有实体与火球受击语义。未发出的玩家起手和待执行进攻也要明确取消／拒绝；不返还已消耗灵力，不删除已飞出的弹。

同一小步可能同时出现双方命中。记录真实先后及余弹后果，不靠数组处理顺序宣称一方毫发无伤。结算前先进入短暂“停止再出手、余弹仍在”的状态；等实际在途弹体为空、未发起手已停止，再开放普通结算交谈与新约战。

## 4. 台词不能把收手变成清弹或无敌

主动停止／越线时可以说：“先收手，还有这一发，避开再说。”双方当前脚点保持，玩家仍能真实走开。不得马上弹出会冻结全世界的对白并说“已经安全”；关闭对白后旧弹仍会飞，那会把结束提示变成埋伏。

首伤后可以显示短提示与收势动作，直到余弹结清再说“刚才这一下先碰到你／我”。退出普通练习范围必须立即停后续起手，但最后一发的去向照常；离场结算不能提前切正式场景，从而利用现有 `changeScene` 清空弹体来假称收手已完整验证。

暂停、失焦、对白的冻结沿现有契约；恢复不能重置满额空档。灰盒“重开”可重建公开合成初态，但不是给正式玩家的战后回血按钮，也不保留这一轮成果。

## 5. 站角、血量与零灵力的反例

| 必须尝试的反例 | 为什么当前规则可能允许 | 最小判定要求 |
|---|---|---|
| 躲墙角、走到300外，等时间获胜 | 散修失去视线会搜索、停射；没有场地任务意识 | 没有实际有效来袭就不算守线成功；练习区外记退出。第一轮不安排可用于躲战的内墙，不把地图边框当对手自败装置 |
| 开护符站角，等对手侧移越线 | 侧移目的点只相对玩家计算，不管练习边线 | NPC 越线不能自动授胜；应停止这一轮并承认站位未支持约定，随后修场地，而非学习 AI |
| 先连发三次烧空抵抗 | 现有命中处理原为敌对退敌 | 首次真实打断即停止后续起手；不读 HP=0 当胜利目标，不回复对手 HP 掩盖越界 |
| 零灵力靠无敌时间站着扛 | `hurt` 后1秒无敌，单回合结束若只计存活会误判 | 纯步法代表成功必须未受伤、无护符/治疗，且该发真实发出并离开/撞到明确承接面；受击是失败而非步法成功 |
| 预告出现便横移一次后站定 | 敌人在**发射时**才对准玩家当前位置，预告不锁定方向 | 不把“预告亮了立刻横一步”写成保证成功；需在发射时保持位移，或看到实际弹道后侧让。须真实手机输入证明 |

零灵力在运动学上有可能：例如180单位间距、24偏移和24受击半径，直来弹接触原身体位置前约有 `(180−48)/260≈0.51秒`；横移24单位理想用时0.15秒。但发射方向会重定向，触控反应/点击派发/加减站位余量尚未计入，这些算术不是可行结论。

点地还受当前 `pathForActor / safeFromThreat` 的145单位避敌范围约束：从安全处点到太近的对手侧面可能被拒，键盘却能继续移动。代表零资源路径必须使用真实可接受的点击，不能只用 WASD 成功外推手机。若必须逐帧抢发射后窗口或靠暂停才过这一发，应缩小候选目标或否决，不改旧伤害/速度凑过。

## 6. 脚点与手机画面先验

C 卡尚无具体地图坐标，因此没有任何已成立的场地。可供根代理做纸面起点的**候选**是把小练习区放在1800×1800独立地图内部：玩家(900,980)、对手(900,800)，相距180；这是为了先看正面一发，不是批准最终边线或站位范围。两人必须实际就位，外围留出可走的离场处。

按非石驿手机缩放0.85、领先55推算，390×844中玩家脚点约(195,468.75)，对手脚点约(195,315.75)，82高旧散修形象的头部约落在246附近，初始正面可望进入先前230..610的保守决策窗。须核对真实图像、HUD、双方身体与可点退身地面，不能只核中心点。

**侧移是更大的视野风险：** 围绕玩家半径210时，最左/右脚点可到 CSS x≈16.5/373.5；加上人物宽度即可能出屏。六秒护符期间对手会持续侧移，不能把一次0.65弧度目的点当作完整运动范围。玩家又能移动，会同时改变对手来向与镜头追踪。

因此第一轮只核对一发起手期间的实际侧移和结清，不先承诺守满六秒或两回合始终同屏。若需要危险中拖镜头才能看到对手，不以自动缩小全图或截断其规则来假称通过；先评审练习边线、初位和本轮实际持续范围。使用 home 槽时仍须明确自定义相机，不能继承 home 的桌面缩放/领先特例却引用非石驿投影。

已有命中、格挡、受击姿态、短冲击与音效可复用，但起手、阻挡、命中、收手必须在真实时点有不同表现。灰盒可简朴，不用胜利纸牌代替看到来弹、护符碎开和双方停下。场边 NPC 不该用旧“清人退敌”的措辞评价一次自愿练习。

## 7. 进入灰盒前的三项决定

1. **一回守线到底判什么：** 第一闸口仅步法／护符，明确一发实际来袭、越线、认输、首伤与余弹的顺序；没有发射和实际应对不能胜，不以血量耗空胜。火球打断只有在这一闸口成立后再开独立对照，不纳入首个灰盒的通过声称。
2. **如何收手但保留因果：** 单一弹源、入局双方≥2、无旧弹/起手，逐小步停止后续进攻，余弹自然结清。需要先有这些边界的真实回归，才可称点到不会归零；不得写“绝不受伤”。
3. **零灵力与侧移是否可读：** 先证明正常点击的无伤守线及离场，并尝试站角、等过时钟、错误护符方向和护符侧移出屏。失败不得追加学习 AI、近战连段、回血奖励或泛用伙伴指令挽救。

这三项值得做小灰盒排除风险，尚不足以认定 C 比 A 更值得生产。人物愿意练什么、这一手为何值得再试与实际打击质感，仍要由根代理完成最小设计并依据运行证据取舍。本轮未改变来源边界；闻朔、约战、边线和回合制度均属 open，不借原作独有能力背书。
