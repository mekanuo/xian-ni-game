# 自愿练场：正式状态与存档接入评估

2026-09-11。**仅方案评估，不是生产批准。** 当前线上仍为已发行 0.7／内容版本 6；一手守线及换来向的实际白盒证据不等于正式第八图、完整续存或真实设备全覆盖。当前依据为 [HANDOFF](../HANDOFF.md)、[SPAR_080_DESIGN](SPAR_080_DESIGN.md)、[ANGLE_GATE](SPAR_080_ANGLE_GATE.md)、[spar-model](../src/whitebox/spar-model.ts) 和正式 contracts／save／model／market 接线。根代理最新回报：桌面／手机连续再次约定、实际绕行与资源保留均已 PASS；该结果只覆盖白盒，正式局部设计与存档接入仍未实施。

本轮只新增本文，未修改源码、测试、配置或资产，未运行构建、浏览器或 Git。

## 1. 最小接入结论

若下一步批准生产，建议作为**石驿后单独一张自愿练场**，使用独立 `SceneId: 'spar'`，内容版本由 6 升为 7；`schema:1` 和 `revision:'return-stone-v1'` 保持。不覆盖 `SCENES.home`，不把灰盒 `createSpar()` 当迁移函数。后者会新建角色、替换 home 实体、清旧 flags、清 checkpoint、置零伤药、指定练法与资源，不能进入正式保存路径。

最小场景清单是八图：现有七图保持原模板，再添加 spar；只有 home 追加一处练场入口，spar 中有一个固定回驿出口和**唯一闻朔实体**。圆线与来向标记可作为地面／固定 scenery，不需要会移动的箱子、计分物或新的 rest。具体实体 ID、入口脚点、完整碰撞与正式镜头尚待生产设计锁定，不能直接沿用灰盒替换 home 的坐标合同。

推荐入口在首章桌边已有真实结束心愿后开放，与旧生活续玩使用同一层事实；不要求先完成旧渠／同行／旧窑／小集，更不能反向把练场成绩设为这些旧内容的入口条件。玩家可以路过、交谈、离场；体力至少 2 的限制只影响约下一手，不影响进出。根代理已确认这个首章归驿后的入口方向；完整局部生产设计仍待收敛。判定采用既有 endingWish／首章实际归来事实，不发明 market.complete，也不改变已有首章结束的含义。

不新建等级、三方向通关列表、奖励或重复领奖账。要保留的是本轮怎么进行、上一手实际怎样结束，以及闻朔所在的位置。三方向属于每回合约定，不是三个任务。

## 2. 推荐的最小 SparState

建议从白盒外层 `SparRound` 中剥离 GameState 和实体引用，剩下真正需要跨保存的活动状态进入 `s.spar`。不在 JSON 里再存第二份 `s` 或 `peer`。

```ts
// 仅候选合同，不是已接入的运行类型。
type SparStance = 'front' | 'left' | 'right';
type SparOutcome = 'hit' | 'dodged' | 'blocked' | 'stopped' | 'outside';
interface SparState {
  run: null | {
    phase: 'positioning' | 'active' | 'settling';
    stance: SparStance;
    positionPath: Vec[];
    positionWaiting: boolean;
    startHp: number;
    startSeq: number;
    shots: 0 | 1;
    blocked: boolean;
    stopReason: null | 'stopped' | 'outside';
  };
  last: null | { stance: SparStance; outcome: SparOutcome };
}
```

`run=null,last=null` 表达初见／尚无结果；`run=null,last!=null` 表达一手已结清、可以近身回谈。再次约定创建新 run，上一手 last 可保留到本轮真正结清后替换；运行中不拿旧 last 当当前结果。这样不必再同时存 `phase=result` 和另一份相同 outcome。若决定逐项搬用白盒五阶段，也可行，但不能两套同时拥有阶段权。

- `startHp` 是比较本次受伤的基准，不是要恢复到的体力。begin 时按实际体力再次赋值；positioning 的旧基准不可用于授胜。
- `startSeq` 与 `shots` 保留白盒“一手只能发一次”的记忆。它们不是日志条数。`flags.projectileSeq` 是实际累计发射编号；在当前独立练场仅闻朔可发弹的合同内，差值才有本轮含义。玩家火球禁用、无落石和其他攻击源，是这个最小方案的必要前提。最小建议继续按白盒在练场内拒绝火球／牵物，不仅 active 时拒绝；否则和平闻朔仍会被当前 player 火球命中，不能再假设不存在场外敌对伤害。若正式要允许空场试火，须单独定义对象与攻击来源，不能沿用本段一源校验。
- `blocked` 记录已实际发生的本轮阻挡，不能恢复时从“护符现在消失了”猜测。当前事件队列可能裁剪；不能把遍历旧日志当唯一恢复依据。
- `positionPath` 保存剩余实际途经点，不能每次导入按当前位置重新计算最短路。否则可能改变北／南绕行、穿回圆心或让出路的人重新被堵。`positionWaiting` 保留此刻停步姿态；只有下一次正常 tick 才重新判断是否可以走，不在 restore 中让他迈一步。
- `stopReason` 先发生者保留。收手后被余弹碰到，当前白盒仍以 stopped／outside 为结果，真实 HP 另外保留；不能把这个优先级误当“没有受伤”。正式回谈可说明“已经收手，飞出的一发仍碰到了”，不改成无伤成功。
- 最小 last 只支持最近一手的具体回应，不证明首次掌握、全方向精通或许照共同见证。若后续设计确实需要这些历史，再新增相应真实事实，不能从一次 last 反推。

`flags.visited_spar` 可沿用既有到访惯例；无需再在 SparState 复制 visited。新 last 或 run 均须有真实到访前提；合法旧档只补空初态，不自动生成一手经历。

## 3. 哪些运行事实必须原样续存

| 所属位置 | 必须保留 | 恢复时不可做的“修复” |
|---|---|---|
| `worlds.spar` 唯一闻朔 | 实际 x/y、朝向、state、hp（若继续使用现有实体字段）、timer、`data.attack/seen/lastX/lastY` 等实际 AI 动态量 | 回原位、对准约定点、重置起手、改成满血的新实体 |
| SparState.run | 当前阶段、约定来向、换位剩余路径／等待、开局体力与发射编号、已发一手、阻挡、首个停止原因 | 把 active 改 positioning；把 settling 当 result；把 shots 清零再发一次 |
| Player | 当前 HP/MP、坐标／朝向、实际路径、无敌时间、护符持续／方向、施术冷却 | 给两格以满足开局门槛、补灵力、撤护符、清受击保护或强行站回圈内 |
| Projectiles | 每发的 id、x/y、vx/vy、life、owner | 重新按当前玩家位置瞄准、回发射点、延长寿命、读档时清弹 |
| flags／事件 | projectileSeq、eventSeq、wardCooldown；仍在生效的起手／施法字段及对白暂停字段 | 用日志数替代编号；重复生成 block、发射、成绩或声音 |
| UI 及通用状态 | paused、pending、dialogue、defeated、selected、time、checkpoint、lastSafe；既有任务和资源 | 强制结算以便打开菜单、恢复时偷偷执行 pending、把旧首章结束重新弹一遍 |

**实体引用恢复必须重新查找** `worlds.spar` 中约定 ID；不能保留 replace 前的 `peer` 引用。正式 tick 只推进一份 GameState。白盒的 `sparTick → tick` 包装不能与正式 tick 再嵌套执行一遍；必须在同一个小步的移动之后、敌人起手之前撤销攻击许可，并在射弹实际推进后结算这一手。

闻朔在 active 时可能因玩家撑护符而实际侧移，所以不能要求他始终等于 front／left／right 的起始坐标。他在下一次 positioning 也可能从上一手的侧移脚点开始。严格存档应验证真实合法地面及相应路线，不能用三个固定点白名单拒绝真实中途档。

## 4. 非战时能交谈，但余弹不能被交谈吞掉

### 当前接线缺口

这不是推测：`model.ts` 的 `interactable()` 直接排除所有 `kind==='enemy'`，`scene.ts` 点中 enemy 时只提示防备而不寻近身点；仅将闻朔设为 peaceful，不能得到正式近身约定。另一方面，`dialogue()` 会置 paused，`tick()` 在 dialogue 时停止；如果把任意 peaceful 状态当可交谈，settling 期间的余弹就会被结果对白冻结。

### 推荐：保留稳定实体 kind，做局部身份例外

最小方案保留 `spar_peer` 为固定 `kind:'enemy',type:'raider'`，让已验证的起手／侧移行为继续有相同输入；**不在 idle 与 active 之间修改 kind**，避免场景精确模板和恢复结构跟着变化。只对 `scene==='spar' && id==='spar_peer'` 增加统一的交互资格：

1. `run===null`，没有余弹、玩家待发施法、未结清牵物；人物实际近身、可见、脚点合法。
2. E、附近按钮、鼠标／触摸点击、自动走近、`canInteract` 与 `interactionPoint` 都读同一个资格，不能只有对白函数知道特例。UI 文案也不能仍叫玩家用火打断他。
3. positioning 阶段由非模态「收手」停止移动；active／settling 阶段同样只有停止后续出手的动作，不直接打开普通对白。
4. 收手／越线立即取消**尚未发出的**起手和后续攻击；已经生成的弹照原速度／寿命／碰撞前行。不能为非战状态清掉这一发。
5. 余弹清空后才写 last 并允许结果交谈；不自动远距离弹结果对白。玩家愿意时走近闻朔，再约下一手。这样保留“亲自再靠近”的过程。

普通手动暂停、设置、失焦和保存仍可冻结世界，是已批准控制方式；这里禁止的是**点 NPC／结果自动对白产生隐含暂停，从而冒称危险已结清**。保存暂停余弹时，应保留那发弹；继续后它依原阶段行动。

新约定可复用已有 `interact/choose`：三个来向是已知 choice ID，不增加自由指令。接受前仍须校验旧弹、HP、距离、当前阶段；对白翻页及 `dialogueWasPaused` 沿现行协议。关闭对白后若原为手动暂停，闻朔不能先走。begin／stop 应采用明确局部动作或专用已有动作意图，不能造一段假对白来调用 choose；若新增 GameAction，`validAction` 和暂停后的重新校验必须同步。

另一方案是固定 `kind:'npc'`，为本场显式调用共享 raider 行为。这会同时改变敌人迭代、视觉、受击对象和威胁判定，成本更高；不建议为了“能点人”先改 kind，再忽略这些差异。

## 5. 连续活动的严格校验

下面是可执行的校验边界，不是对任意 JSON 历史真实性的证明。

| 阶段 | 合法关系 | 应拒绝／禁止误结算 |
|---|---|---|
| 无 run／初见或结果 | 闻朔 peaceful、没有未结清起手；last 若存在必须是合法来向／结果；人物可停留在上一手真实脚点 | 无 last 就凭坐标补练习经历；result 同时带未结清敌弹 |
| positioning | 当前 scene=spar；stance 固定；闻朔 peaceful；shots=0、blocked=false、stopReason=null；剩余路径和等待合法 | 恢复时瞬移到站位、旧弹未清便进入新 positioning、pending begin 跳过真实到位 |
| active 未发 | 玩家按现有边线规则仍在圈内；闻朔为实际 chasing/casting；保留 attack 进度和实际朝向 | 保存后倒退到零起手；即将越线却先发射；根据等待时长授胜 |
| active 已发 | shots=1；闻朔无下一次攻击许可；有当前发出的在途弹，阻挡／受伤按实际小步更新 | 又发一手；把现在 hp 与任意历史最大值比较；强制闻朔回约定坐标 |
| settling | 闻朔 peaceful，不再积起手；首个 stopReason 或真实 HP 下降解释停止；余弹仍属于当前场景 | stop 就清弹；stopReason 与 HP 不能同时存在；把主动止步记 dodged |
| 结清瞬间 | 当前小步完成射弹推进，再按既有优先级写 last、清 run | shots=0 仅因弹列表空就记成功；跨图回调用“离开圈”补一场胜利 |

数值：run 的 startHp 应为合法开打基准 2–4；shots 为整数 0 或 1；编号是安全非负整数。活动中 `projectileSeq-startSeq===shots` 仅在练场没有其他发射源的前提下检查；run 清空以后，玩家去其他地图继续施术，不能拿上一回合的编号继续限制全局增长。弹 id 不能重复，实际练场弹应对应本轮发射编号且来自 enemy；寿命／速度按当前规则验证，不为通过存档延长它。

换位路径应限制为获准站点和绕行点组成的剩余合法折线，并校验当前脚点到首个点这一段；不能允许存档指定任意穿圆路线。初次在圈内招呼位置走出是已批准例外，后续外圈换位不穿半径 110 区域。必须以真正途中暂停导出确定合法边界，别把未走到就位点的中间脚点误当非法。`positionWaiting` 只在 positioning 有意义；其布尔值是上一实际小步结果，不以导入时额外模拟来“纠正”。

阶段写入应在同一个正常小步收束。若实现允许保存恰在 shots 增加但 phase 尚未收束的瞬间，需要保留并验证这个实际可出现的过渡态，或先让写入点落在小步之后；不能让 decoder 通过猜测替运行逻辑完成那一步。

## 6. 出入场、同伴和安全点

练场无 rest，`lastSafe.scene` 不得为 spar。入场保留原 lastSafe 和所有实际资源，成功、失败、再次约定也都不改变安全点。回驿后玩家可按已有规则亲自静息，这与“回合结束补满”不同。

当前 `changeScene()` 会清 projectiles、护符、待发施法和 pending。因此必须在进入该函数前处理练场离场意图：

- run 无或已结清、且无旧弹／待发起手，才真正执行出口切图。
- positioning／active 想离场，先当场收手并撤销未发起手；若有余弹，进入 settling，仍留在真实场地。用户可走、挡、暂停，弹结清后再实际点出口；不必新增自动排队跨图。
- 不能先换 scene，再用旧圆线坐标判断越线；也不能先调用通用 changeScene 清弹，事后补 stopped。
- 正常离场保留最后结果、闻朔真实位置与资源；下次回访不是 createSpar。已结清回场可重新近身约定，仍须实际换位。

最小生产范围建议**不增加 xu_spar 副本**，不把许照拉入可拦截这一手的位置，否则当前 shots／blocked 判断可能把同伴代挡当成玩家侧身成功。玩家从 home 与她实际同行时，入口要明确约她在驿内等候，再独自进去；本次 wait 是真实选择，保存她的真实驿内脚点。她原本在其他图等候／拒绝时，完整保留原状态，不转移、不新生副本、不自动再邀。返回也不自动写共同练习或恢复 following。

据此可对新图限定 `scene==='spar' ⇒ companion!=='following'`，但这个限制不能反向施加在旧七图或旧版合法档上。若后来决定允许旁观，须另做合法候点、射弹隔离与在场合同，不把复用 market 副本当免费接线。

练场提示只在练场或玩家主动问起时出现，不覆盖 home 已进行的 repair／harvest、旧渠落笔、同行回程或小集记事。结束一手不设置 `ended`、`endingWish`、`returned`、`sharedJourney` 等旧主线事实。

## 7. 6 → 7 与单层 checkpoint 迁移

现有 `save.ts` 的 restore 分别解码外层世界与一层 checkpoint，内层 `checkpoint` 必须为 null。这个结构保留；不能把外层练场状态合并进旧内层，也不能丢弃内层以降低验证难度。

建议顺序：

1. 支持的来源仍是缺省 contentVersion 的最早档、2／3／4／5／6，加新 7；显式 `1`、未知版本、字符串版本继续拒绝。
2. 所有小于 7 的来源，先拒绝自带 `spar` 账、spar 世界、spar 场景／安全点、新入口／人物或 `visited_spar`、约定的新命名空间历史。严格旧实体清单还要先验证，不能先追加／清洗后让混入数据通过。
3. 原链 1→2→3→4→5→6 按原清单及旧事实继续；将当前七图清单独立命名保存。不能只把 `scenes` 改成八图，就使 v6 也要求第八图或允许混入第八图。
4. 对完整源 v6 执行所有原验证：life、canal、journey、kiln、market 以及七图精确实体。通过后才添加 spar 初始地图、唯一闻朔、回驿出口及 home 新入口；初态为 `spar:{run:null,last:null}`。入口显隐仅按已确定的开放条件派生，不授予练习经历。
5. 置 contentVersion=7，再执行八图及 SparState 的新验证。新版世界必须显式有 spar，不用“缺字段就默认重置”兼容损坏的 v7。
6. 外层和内层独立走上述过程；外 7／内 6、外 6／内 7 均可分别合法解码，不要求嵌套版本相等。任何一层非法都拒绝整份导入，当前运行局面保持不变。第二层 checkpoint 仍拒绝。

**现有版本分支需逐处改，而非只换一个数字：** `beforeMarket=version!==6`、`version!==5&&version!==6` 以及 manifest 中 `version===6` 等写法，都必须正确排除新 7；否则 v7 会被当旧档重复迁移或拒绝已有 market／kiln。旧五图／六图中需要验证新增入口的调用也应按 `>=` 范围接续，但源模板不得污染。

固定旧 fixture 原样保留。新一版实际 QA 导出另存路径，不能覆盖旧 0.7 固定档来凑迁移测试。旧档没有闻朔的历史，也没有可迁移的灰盒结果；白盒导出若以后提供，只能保持隔离，不伪装合法生产 v6 升级。

## 8. checkpoint、重试和保存导入不是同一个动作

### 保存／导入

`restore()` 当前解析并迁移，并不推进 tick；维持这个职责。UI 手动载入／设置导入已有“先恢复缓存、设 paused=true、再 replace”的顺序与 endingShown 防重弹逻辑，新增练场必须沿用。读入活动中一手后，人物、余弹、起手、资源和 run 完全保留；显式继续后才推进。

### 自动 checkpoint

现有 `checkpoint()` 会剥掉 pending／dialogue 并设 paused=false。因此不能把“每次选项后调用 checkpoint”直接照搬到活动中并宣称它是原样手动快照。建议只在新图实际入场的清洁状态，以及一手**已经结清**后更新恢复点；开始／结果交谈必须在关闭对白、状态收束后才决定写入。手动保存仍允许定位中、起手中、弹飞行中、暂停中。

一手结清 checkpoint 要保留刚损失的体力与灵力，不能记录开局资源。结清前的回滚是否保留上一回合，应随完整 checkpoint 世界回滚，不只回退 SparState。所有新写入 checkpoint 仍是单层，不能内嵌先前 checkpoint。

### 重试／撤回的真实冲突

当前 `model.ts` 的 retry／retreat 最后明确执行 `hp=4,mana=6`、清 projectiles／pending／path，即使 restore 得到的是带伤、低灵力状态。因此**不能把这个通用分支作为“再来一手”或普通练场恢复接口**。若直接暴露它，练习失败后点重试可免费补满；若在余弹阶段可点，还能直接消除这一发。

最小建议：练场正常活动、settling 和结果阶段只提供收手／结清／实际离场／再次约定；通用 retry／retreat 对这些正常状态明确拒绝，不仅隐藏按钮。一手用 HP≥2 开始、首次受伤即止且只发一次，在已验证规则内不应进入体力归零；若生产环境额外产生 defeated，应单列为接入反例，不能让常规路径依赖它回血。

如生产设计仍要求练场具有显式“恢复检查点”，需增加**只针对练场的完整快照回滚**语义：恢复 checkpoint 中本来存在的 HP/MP、弹和阶段，不再强制满值；它是明确重试，不是继续上一手。无法与旧关卡通用重试无歧义区分之前，不接此按钮，也不改掉旧章节已承诺的失败恢复。导入一个合法 paused 活动 checkpoint 则必须继续该活动，不能为便于重试把它改成空场。

## 10. 交回结论

生产接入的最小新增不是“给灰盒加一个保存按钮”，而是：独立第八图、唯一闻朔与局部非战交互资格、可续存的一手状态、清洁退出边界，以及保持旧来源清单的 v7 迁移。最需先定案的是**通用重试的满资源行为不可借作再约**，以及**结果对白／切图必须等待真实余弹结清**。

这些边界可以在不增加境界、强制主线、奖励账或同伴训练系统的情况下收敛。本文未实施、未验证正式续存；根代理确认局部方案后才能安排代码与相称测试。
