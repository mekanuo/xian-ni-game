# 构建与验收结果绑定

仅从0.7开发分支接入。0.6正在运行的矩阵与发行继续采用其冻结文件审计，不回写本工具或追认自动绑定。

`npm run verify` 在模型测试和构建前读取源码/工具输入，构建完成后确认输入未变并保存 `qa/verification.json.fingerprint`；浏览器矩阵结束后再次比对全部输入与dist，才允许PASS。`deploy-pages`在任何Git/网络操作前检查同一指纹，并在复制dist前再次检查。旧的无指纹PASS会被拒绝。

输入范围是当前仓库的src、public、tests、scripts及构建/依赖锁定配置；文件新增、删除或内容变化均比较SHA-256。dist独立递归比较。HEAD、时间戳与文档不参与，因此提交验收证据、更新交接文档后仍可发布同一已测包。独立白盒入口/配置不属于正式构建输入，但src/whitebox仍被tsc读取，所以在源码范围内。

这不是签名、原子文件系统快照或任意Vite依赖图解析器。须继续冻结受测候选并控制Node、依赖安装和进程环境。qa目录不在源码指纹内：现有首章脚本会产生当前版本真实导出，不能把全部fixtures当不可变输入；历史夹具来源和QA结果真实性仍须分别核对。改变构建入口、导入仓库外资源或更换工具链时，须更新收集策略。

验证记录：33项辅助模块测试通过，涵盖新增/删除/同长度内容变化、构建配置、分离dist、损坏清单、符号链接拒绝及允许文档/QA更新；TypeScript通过。另用临时目录运行真实verify/deploy入口，确认无指纹旧PASS、改过的dist与模型测试期间源码变化分别被拒绝，均未启动浏览器或执行发布。这些是工具验证，不是0.7整版游戏PASS。
