# 全书梳理策略（紧凑覆盖 + 重点深挖）

## 目的

先得到一份可追踪、连续、不会漏掉主线的全书结构索引，再把真正适合改编为游戏的篇章做深度拆解。两层产物分开计数，避免用局部精读或旧的关键词扫描冒充全书完成。

## 第一遍：剧情弧连续覆盖

按源文件章节顺序处理，以连续剧情弧为单位覆盖，默认每弧 20–80 章。每弧保留固定的短卡：

- 事件：该弧的起点、转折、终点，最多 8 条。
- 角色/目标：主要角色、关系变化和阶段目标。
- 冲突/选择：可改编为玩法的处境、风险和选择。
- 规则/资源：该弧新增或验证的世界、战斗、关系和资源规则。
- 因果/证据：弧前承接、弧末结果、关键源文件行号和章节边界。
- 可信度：事实、角色陈述、传闻、研究推断分开标注。

第一遍的目标不是为 2047 章逐一写长卡，而是确保每一章都属于某个连续剧情弧，并且每弧有主线变化、角色动机、规则、因果和证据。每完成一个剧情弧落盘一次，并在 `PROGRESS.md` 记录下一弧的章节和行号。

## 第二遍：高价值篇章深挖

只有在第一遍连续覆盖通过后，对以下篇章增加完整十字段卡、角色关系、系统化规则、情绪曲线和可玩化候选：

- 王林人格和关系发生不可逆变化的篇章；
- 修炼体系、法宝、因果、轮回等规则首次建立或反转的篇章；
- 有明确目标、风险、选择、反馈的冲突段落；
- 适合作为教程、章节关卡、伙伴成长、探索事件或终局内容的篇章；
- 能代表世界观气质但不依赖复制原文的场景。

## 验收口径

1. 只有正文实际读取、章节边界可定位、证据行号存在的剧情弧才计入第一遍；弧内章节范围必须连续。
2. 旧 agent 报告、标题扫描、关键词扫描只能作为导航，不能计入连续覆盖。
3. 局部文件若缺章或在输出中截断，标记为“部分产物”，不得按文件名推断范围完成。
4. 在第一遍完成前，不创建游戏核心设计规格；只能记录待验证的改编候选。
5. 每个剧情弧必须可独立恢复，不允许依赖临时进程或未提交的内存状态。

## 当前执行顺序

恢复时先读`../PROGRESS.md`顶部最新调度，再检查同一句柄及其输出文件；本文件不维护会过期的固定起读章号。不得按旧记录从111章或26章重新开始。

当前批次采用40个物理章独占一个文件、每5章保存一次六项短卡；单卡约300–600中文字，疑点单列。正文读取块配足输出预算，200–350行可作为起点，不强制按固定行数切块。只有实际输出截断、缺口或明确待核事实才补读，禁止为块长、格式或重复汇报重读完整正文。

并发调度由主线程负责，子代理只写自己获派的文件，不派下级、不修改总纲与进度。八路曾尝试但第七路遇线程上限；具体当前句柄仍以进度顶部为准，不能从授权数量推断实际在跑数量。

第一遍提取、主线程读报告、局部原文核查、总纲聚合分别标记。旧提取稿不因年代较早自动作废，也不因自称完整自动通过；只对缺证或冲突范围核查，不重做已证实的覆盖。已有逐章细卡保留，不为统一格式整批重写。
