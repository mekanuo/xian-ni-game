# 雾岭旧渠 0.4 实施计划

2026-09-11。用户已授权外出期间自主推进；设计边界见 design/ADVENTURE_040.md。

目标：首章完成后，玩家真实接信、进入第五图，用零资源分水或留势截水清渠、验水、听取确认并亲自归驿落笔。旧四图和生活委托完整保留。
架构：GameState 是唯一事实；canal.ts 裁决新工序，model.ts 提供碰撞、伤害、切图与事件端口。场景只绘制事实，UI 只发动作。保持 schema/revision，内容版本迁至 3。
技术：现有 Phaser / TypeScript / Vitest / Playwright；不改依赖。

## 全局约束与接口

- 隔离目录 .worktrees/canal-040，分支 feat/canal-040。主目录完成 0.3.1 发布。未经完整验收不覆盖公网稳定版。
- SceneId 新增 canal；SCENES.canal 引用 canal-content.ts。旧 SCENES 四图清单不得改动以保持旧档验证。
- GameState.canal: stage(unaccepted/active/verified/ready/complete), inspected, cleared, method(null/diversion/hold/clamp), sharedInspect, sharedVerify, usedClamp, work(null 或 kind(divert/restore/clear),elapsed,start), drain(0..1), flow(0..3), surge(null 或 0..1.2)。分水/截水由实体真实位置和支撑决定，不能另存一个最后点击的路线。
- canal-content.ts 输出 CANAL_SCENE、CANAL_POINTS、CANAL_CHANNEL、CANAL_SIDE；实体 canal_diverter(600,350), canal_stop(1280,350，止水槽1200,350), canal_eye(1230,410), canal_screen(1100,540), canal_inspect(880,610), canal_tub(350,930), canal_keeper(260,960), canal_rest_mid(880,720), canal_to_home，xu_canal，两只 beast，canal_scent。渠底碰撞与干湿画面共用矩形常量；永久岸路不受水位影响。
- canal.ts 端口继承 LifePorts，加 hurt(s,source,reason)。输出 createCanalState, canalChoices, canalChoose, canalInteract, canalTick, canalInterrupt, canalBeforeExit, canalMaintainSupport, canalPullReason, canalObjectChanged, canalObjective, canalDescription, canalWaterState, canalObstacles, canalCompanionTarget。具体签名与适配由规则模块文档注明。
- 旧压扣位置扩展 canal；旧药囊状态追加 scene(workshop/canal)，新实体 canal_scent，仅一个生效气味。气味只在所属当前图倒计时；旧档补 scene=workshop。
- 入口复用 home.to_creek：完成首章且接信后弹明确目的地；原首章进入行为不改变。切图过程只能调用统一模型入口。home.table 追加邀请/落笔选项，不复用首章 ended 结局开关。
- 工作与水位计时遵循暂停/对话/失焦；移动、施术、受击、切图打断工作。波涌预告1.2秒后最多一击并上岸，原伤害保护仍生效。
- B 保持留势8秒。真实设备路径有余量才通过；不修改术法数值掩盖空间问题。

## 任务与里程碑

1. 合约与可测试白盒：根代理改 contracts/content/model 接口；独立规则代理仅写 canal-content.ts、canal.ts、tests/canal.test.ts。以真实 act/tick 证明两个水板优先级、零资源路线、持物不能清理、计时冻结、突然来水安全退出。
2. 存档升级：独立代理仅改 save.ts、tests/canal-save.test.ts；验证原 0.2/0.3 外层与 checkpoint、不补资源、唯一扣、唯一气味、未知版本拒绝。更新旧测试版本断言由根代理承担。
3. 集成与实机白盒：根代理接 model/life/UI/scene，先构建、单元测试，再在真实浏览器走 A/B 和手机留势窗。测试失效时先找原因，不注入进度假装走通。里程碑测试通过推送 Git。
4. 美术和体验：按石驿已认可风格独立原画、检修装置层次、水线和台阶；清晰贴地、名称避让、手机DPR3、短窗提示和环境声音。人物回应实际结果；无逐帧动画虚假宣称。
5. 完整验收发布：旧两路、生活委托、新两法、夹扣/药囊变式、旧存档与重开；桌面/矮窗/手机检查。源码提交推送后 clean tree 发行、公网hash与真实输入核验，更新交接。

逐项测试先写失败断言，再实现、运行并记录。根代理控制 Git、构建、浏览器和公开发布，代理不可并行运行浏览器或改 Git。每个输出按事实记本地/推送/公网状态。
