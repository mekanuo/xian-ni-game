# 碎崖候选：空间先验执行顺序（待 0.7 发布后启动）

本计划只收敛第一份可执行检查，不批准正式第八图、生产美术或存档升级。当前0.7仍冻结验证，不能执行下列代码动作。用户已授权自主取舍，不重复询问身份、平台、画风或既定发布。依据 design/CLIFF_NEXT_RISK_REVIEW.md、design/BUILD_BRIEF_CLIFF_WHITEBOX_DRAFT.md、design/CLIFF_WHITEBOX_COUNTEREXAMPLES.md；所有地点与规则增量均为open原创。

## 第一份交付只回答空间是否成立

从0.7实际发布来源及文档里程碑创建独立工作树和分支，记录真实起点。不给正式dist、七图注册、生产存档或公开Pages增加候选入口。根代理负责Git、浏览器和构建，同一时刻只开一个软件GPU浏览器。

### 1. 固定待推翻的问题

先写合同测试，再落实候选的完整矩形墙体：

- A/B、L、H及其合法边角、U/E确实可站，身体采用现有17轴向包络。
- 实际move/tick可以走完两路及反向；不以点坐标直接赋值代替行走。初态位置属于显式合成前置，要与过程证据区分。
- B到第二段的任意通路必须先进入L接近区，不能先到H/U/E；反向同查。去掉L唯一连接的反事实连通检查可辅助定位，但不把它冒称运行地图有新墙。
- L和合法边缘点直接点击E时，记录原生40网格/直线裁短后的实际路径；不能假定必走外槽，也不能偷偷设H必经标记。
- H四角分别点U以及反向点H，记录实际路径和到达，不只验中心线。转角如果没有容错，先改局部地形；不改全局身体、网格或移动速度。

把当前中心坐标作为候选输入，完整外围必须在报告中给出，不能仍用“仅连接列出路线”代替碰撞。若初稿不能成立，保留失败证据和具体反例，再做一次局部修订。无法在既有导航下兼顾可达与有意义选择，则搁置，不加机关补救。

### 2. 确认复用接口与最小镜头

独立home槽只是模型容器，不等于生产石驿镜头。白盒需显式采用目标普通地区的镜头比例与领先量，按实际display/scene函数确认；不继承home桌面特例再沿用通用投影表。使用既有白盒入口模式和公开合成初态，检查API只有只读inspect、screenPoint及几何说明。

空间模型可行后，最小运行页面只呈现墙体、可走地面、站位、来源、真实角色与点地/键盘/看路/回身。HUD的实际尺寸、文字和布局要匹配目标游戏约束，不能通过隐藏生产菜单让候选“手机同屏”。不开始正式绘图。重点检查390×844、1280×500、1440×900，保留完整身体和可点脚区的矩形，含合法边缘站位及正常提示；不只看源头中心。

### 3. 首次碰撞，再决定是否值得做完整危险

沿既有Projectile合同和共享裁决验证源口确实出石、途中不被不相关外围吞掉、首先碰到岩鼻或24受击圆。复用定向护符与伤害，不复制另一套碰撞。现有simulationPorts没有spawn入口，若确需开放，只加最小共享入口并说明受测用途，不把写接口挂到浏览器。

先记录S2主线与内侧碎片各自的真实首次接触，以及U→E两线横穿。比较有/无内侧碎片时的实际路线选择：若只是多一团永远撞墙的效果，仍不能证明玩家选择了掩蔽。首撞通过不等于完整往返或趣味通过。

### 4. 第一闸口

上述具体模型反例和三视口实景齐备，形成单独空间审查结论并及时提交推送。只在空间关系和读路余量成立时，继续原风险合同的周期、正常速度零灵力无伤往返、相位、失败退回、护符、暂停与有限报告。它们不是本轮提前勾选的通过项。

仍然不得接正式大地图或宣称新章完成；候选被否决也是有效设计结果，应记录为什么，再按既有路线图选择值得制作的内容。
